# Agent 推理与工具行为模式（agent-reasoning-patterns）

> 派生说明：本专题源自编程专家 2.0.3（原作者智慧&半岛-www.52yuer.cn，原包声明 MIT）。编程专家 Pro 的共同授权、凭据、验证及按需规则见 [执行原则](../SKILL.md)；本专题的历史固定流程不扩大用户权限。

## 铁律

```
思考要深而全，输出要短而准；每个动作前有预期，每个动作后有对照。
```

## 适用场景

- 多步 agentic 任务（工具链操作 / 代码修改 / 长链验证 / 批量治理）
- 工具行为不确定、接口变更、输出冗长等"习惯性损耗"的治理
- 希望提升单步推理质量与工具使用效率

## 不适用场景

- 单步信息查询 → 直接答，不套流程
- 纯行为/数据边界问题 → `ai-coding-governance`

## 模式清单（16 条：决策级 10 / 操作级 4 / 验证级 1 / 输出级 1）

### 一、决策级（行动前）

1. **任务复述与编号**：把散装指令归纳成编号分组后再动手——先让"要做什么"收敛（如 8 条散指令 → 4 组），再排动作。
2. **平台与约束读取**：先识别当前平台的机制信号（钩子 / 门禁 / 审计 / 评审要求），据此决定动作顺序（如：钩子要求先确认接收再给计划）。
3. **用户风格对齐**：从指令措辞推断期望的详略与节奏（"think quickly" → 压缩计划；单字问候 → 单句回应）；风格对齐 ≠ 内容缩水。
4. **环境事实与信息需求先行**：动手前先实测环境（运行时版本 / 工具可用性），再列"我需要知道什么"清单；按清单设计最小采集动作，一条命令能取多项时合并，并逐段说明每段职责（容错 / 限幅 / 防噪）。
5. **工具冒烟**：首次使用的工具 / 接口，先发一个最小泛调用验证行为与返回形态（如泛查询先验搜索工具），再发正式调用；冒烟结果并入下一步理由。
6. **失败即换工具（不硬刚）**：工具返回空 / 报错时，先归因（接口性质不匹配 / 参数问题 / 环境缺项），再换等价通道（search→fetch / 系统 Python→venv），而非重复调用同一条路。
7. **候选 + 反选**：做选择（技术 / 路径 / 方法）时列 ≥2 候选，每个给采用或否决理由，选与需求最对齐者；否决理由要写明。
8. **依赖驱动探索**：读代码从"被引用但未见定义"的符号追向汇聚点（多处 import 的 config → 优先读），用依赖链代替漫扫。
9. **带预期读文件**：打开文件前列"预期得到什么"（若干点），读后对照——不符处即信息点。
10. **基于实据的现状确认**：修改前引用"当前实际内容"（原文块 / 刚落盘的实测输出），禁用印象代替实况；引用范围限本会话实读。

### 二、操作级（改动前）

11. **最小差异设计**：编辑前明确 old/new 精确块、作用范围（replace_all 开关）、单点定位；能改一行不重写十行。
12. **效果预测**：改动前一句话预测后果（含反作用：性能 / 渲染 / 边界 / 他处引用）；预测与实测不符时记入归因，防"改了再说"。
13. **差异清单式接口变更**：改签名 / 返回类型 / 契约 / 数据结构时，列「差异项 + 保持项 + 调用链同步」三栏清单再动手；禁只改被依赖端而不同步调用端（含早退 / 错误分支行为）。
14. **格式细节显式化**：出手前确认边界细节（换行 / 追加 vs 替换 / 引号配对 / 路径形态），把"顺手会错"的细节变成显式检查项。

### 三、验证级

15. **验证失败三向裁决**：断言失败先裁决『实现 bug ／ 测试(断言) bug ／ 期望(需求)不一致』三类——实测取证后分别处理（修码 / 改断言 / 改文档或问用户）；禁一律当实现 bug 修，亦禁一律改测试。

### 四、输出级

16. **输出经济性**：内部推理求充分（证据链 / 归因 / 探针不省），对外输出求克制——结论优先、无客套、不重复已知；汇报点 = 阶段产出 / checkpoint / 收尾，不做每步播报。

## 与六步闭环的挂接

| Step | 应用模式 |
|---|---|
| Step 1 分析 | 1 / 3 / 4（复述编号 / 风格对齐 / 环境与信息需求） |
| Step 2 方案 | 7 / 8 / 10（候选反选 / 依赖驱动 / 实据确认；读文件用 9） |
| Step 3 执行 | 5 / 6 / 11 / 12 / 13 / 14（冒烟 / 换工具 / 最小差异 / 效果预测 / 差异清单 / 细节显式） |
| Step 4 验证 | 12 对照落盘（预测 vs 实测）；15 三向裁决 |
| Step 5 交付 | 16（输出经济性） |

> **派生适配**：工具动作由实际问题和证据选择，不规定内部推理段数。

## 工具动作与证据规划

依据已知事实选择下一步取证或修改，明确验证结果如何影响判断。只在存在实质取舍时比较方案；简单查询无需凑候选、词数或段落。对用户报告结论、证据、假设和待验证项，不要求披露内部思维链。

## 按任务选择投入

小改动直接核对，复杂目标围绕行为/状态/数据边界安排短计划，长任务保留可恢复检查点。领域参考按主入口按需读取，不用固定内部字数或格式评定完成度。

## 高阶思维模式（前瞻 / 集成 / 实证 / 纠错）

> 三层定位：五段式＝单步推理怎么排序；强度分档＝思考取多深；本节＝跨步骤的思维形态。七条均为操作化判据，禁写成理论综述。
> **边界声明**：七种模式属**内化型思考**——在推理过程中执行，不在对外输出中显式展开（对齐模式 16 输出经济性）；其动态思考深度由「思维链强度分档」承载，禁另立条目。

| 模式 | 规范判据 | 反例（禁止） | 与既有条目关系 |
|---|---|---|---|
| 分支前瞻与回溯 | 复杂档段 4 列 ≥2 分支并按「预期信息增益 × 可逆性 × 验证成本」打分；分支被证伪或同签名失败 → 回退到**上一分叉点**换分支，已验证产出不回退 | 单线硬推到底；失败后推翻全部已验证结论从原点重走 | 段 4 候选取舍的跨步扩展；模式 6「换工具」为其一型；回退铁律给轮次上限 |
| 多路径集成 | 复杂档结论（根因 / 影响面 / 选型）须 ≥2 条**独立方法**得出同一结论才落笔（grep + LSP、实跑 + 静态、两处独立证据）；结论冲突 → 回证据侧三向裁决，不取「写得好的」 | 单一证据链下结论；用同源证据（同一 grep 的两次引用）冒充多路径 | G1「以 grep 为准」为其冲突裁决实例；模式 15 三向裁决承接冲突 |
| 工具实证 | 可实证的中间结论（数值计算 / 正则匹配 / SQL 生成串 / 路径解析 / API 行为）禁脑内推演，须当场用工具验证（CLI 断言 / grep / 真实调用）后再进入下一步推理 | 「应该能匹配」不跑就当已验证；把 lint 通过当功能正确 | 铁律「每个动作后有对照」的中间步强化；真人功能验证硬约束同源 |
| 逐步一致性检查 | 每次工具返回后先对照第 5 段「预期结果」：符合 → 继续；不符 → 定位矛盾归属哪段假设，**局部回溯修正该假设**再前进 | 发现矛盾仍硬进；静默改口径掩盖（「先这样，后面再看」） | 模式 12「预测 vs 实测」+ 模式 15 三向裁决的每步化 |
| 沙盒预演 | 不可逆 / 安全相关动作执行前，先在零风险载体预演（dry-run / diff 预览 / 副本环境），预演符合预期才落真盘 | 对生产 / 真盘直接首跑 | 安全闸门的执行侧细化；轻量档仍须最小验证 |
| 链内纠偏留痕 | 在**同一条推理链内**推翻先前判断时，须写全三段式 `旧结论 → 触发信号（反例 / 新证据 / 矛盾输出） → 新结论`，并留在当前产物内（推理文本 / plan / 交接块） | 以「更正一下 / 其实应该」一笔带过；直接覆盖先前结论不留痕 | 与「逐步一致性检查」分工：该条管每步对照预期，本条管**改口留痕**；跨轮重试走「失败计数与升级」 |
| 防套路化 | 遇「看起来眼熟 / 以前处理过」的问题不得按旧经验直接下判——先探测潜藏复杂性（读实码 / 跑最小实证），发现有隐藏复杂度即升档深挖 | 对熟悉的东西做模式匹配；凭「上次也是这个原因」跳过实据 | 对齐工作区判据 `isn't just pattern-matching to the familiar`；模式 4「环境事实先行」为其前置 |

**启用档位**：复杂档全用；常规档按需取多路径集成 / 工具实证 / 逐步一致性检查 / 防套路化；轻量档豁免。

## 验证自检（元验证）

> 定位：五段式＝单步推理怎么排序；强度分档＝思考取多深；高阶思维模式＝跨步骤思维形态；本节＝**验证手段自身的可信度**——写 / 改断言、探针、复现脚本时，先自检该手段。与「工具实证」分工：工具实证管中间结论要当场实跑，本节管实跑所用的验证载体本身可信。

| # | 判据 | 命中即该问成立 | 反例（禁止） |
|---|---|---|---|
| ① 失败原因正确性 | 修复 / 复现类任务的红色证据（修前失败）须**指名目标缺陷**（失败信号＝目标缺陷的特征） | 失败输出含目标缺陷的特征串 | 因环境 / 路径 / 权限 / 数据缺失等非目标原因失败，却当作复现 |
| ② 确定性复跑 | 含随机 / 时序 / 并发 / 外部依赖（缓存 · 网络 · 文件系统）的验证，同条件复跑 ≥3 次结果一致才采信；不一致先归因，不稳定项降级「已知限制」 | 复跑记录 ≥3 次一致 | 单次通过即采信；把不稳定当已通过 |
| ③ 期望值独立来源 | 断言 / 探针的期望值来自**独立依据**（手工推导 / 独立实现 / 官方文档 / 实测基准） | 期望值可溯源到独立依据 | 以被验实现自身输出作期望值（把缺陷固化成「通过」） |
| ④ 基线防污染 | 修复类交付前以干净基线复跑一次、证明「未修态仍失败」（补丁未把基线 / 断言一起改绿） | 基线复跑证据 | 只验修后通过，不验修前失败 |
| ⑤ 断言防守性 | 关键断言（守卫 / 校验 / 边界 / 契约类）须堵住**低成本假修复**（删校验 / 跳边界 / 砍泛型 / 绕过分支） | 断言覆盖失败路径 | 仅覆盖 happy-path 单一修法 |

**设计期前置**：产出优先选**可机械验证**形态——能断言的不靠肉眼、能复跑的不靠单次、能反例的不靠举例。

**启用档位**：L3 全用；L2 按需取 ①③；L1 豁免。

**分工**：模式 15 三向裁决管「断言失败后的归属」（实现 / 测试 / 期望）；SELF-AUDIT 证伪行管「关键结论构造反例」；本节管「验证手段自身是否可信」——三者攻击对象不同，不互替。

## 显式 Method 协议（编码类任务 4 步硬序）

1. **先复现**：改动任何东西之前，读相关代码并跑一遍失败命令。
2. **先假设再最小编辑**：对根因形成假设，做**能验证该假设的最小改动**。
3. **每步验证**：每次实质改动后重跑测试 / 构建；仍失败就**重读输出**，不重复同一次编辑。
4. **治因不治标**：修根因，不做症状修补。

配套三条：不得为让测试通过而改测试（除非用户明确说明测试错）；改动保持最小且与既有代码风格一致；收尾给「根因＋改了什么＋通过的证据」三件。

## 推理侧重校准

- **必写三段**（每轮工具调用前至少覆盖）：行动承诺（下一步＋理由）、现状复述（已知实据）、验证承诺（跑起来看结果）。
- **从简两段**：选项枚举、自我纠偏——不强制推翻已述判断；质量靠**动作前想透**，不靠**动作后返工**。
- **分档挂钩**：按任务影响选择验证与交接投入，不规定内部思考段落。

## 验证

- 任取一次多文件改动，回看是否满足 11 / 12 / 13（最小差异 / 效果预测 / 差异清单）。
- 新工具首用是否有冒烟记录（模式 5）。
- 交付消息是否结论优先、无重复播报（模式 16）。

## 协同路径

- 与 `execution-safety`（失败计数与升级）互补：模式 6 的"换工具"须先归因，再计入失败基线。
- 与 `task-decomposition-and-execution` 互补：模式 1 是其"需求分析"步的输入习惯。
- 与 `delivery-assurance`（SELF-AUDIT）互补：模式 15 / 16 分别为其验证与输出侧的细化。
- 边界问题（数据 / 权限 / 防作弊）→ `ai-coding-governance`。
- 外部事实与引用须回源（禁凭记忆代答、禁构造 URL / ID）→ 同 `execution-safety`「写码前实码确认」的域外形态段。
