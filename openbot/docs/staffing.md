# 招聘与组群：在对话里招员工、组群聊

不用填「新建员工」表单，也不用去「新建群聊」页逐个挑人：在对话里跟小管家（你的「我的分身」）说一句需求，它替你
拟好一份草稿，对话里出现一张卡片。你在卡片上看全文、改几处、按确认，才真正建好。按确认之前，什么都不会创建，也不会
改动。

能做的事：

- 招一位新员工（可以基于你的角色模板）；
- 改一位已有员工的资料、技能、应用和定时任务；
- 用已有员工组一个新群聊，并定好回答顺序；
- 调整一个你发起的群聊：加人、移人、改顺序、改群名。

不做的事：删除员工、解散群聊。这两件风险高，仍在原来的页面上操作。

## 让小管家招人

在和小管家的对话里直接说，例如：

> 帮我招一个小红书运营，每周规划选题、写笔记初稿、回评论区的提问。

小管家会先看一眼你现有的员工、群和角色模板（有合适的模板就照模板拟，并告诉你），缺关键信息最多追问一轮，然后出一张
「招聘「小红书运营」」的卡片，并在卡片上方用一两句话说明为什么这么拟。

**起草时被拿掉的东西写在小管家的话里，不在卡片上。** 你提到的模型不在可选范围、某个技能或应用你自己给不了、某条
定时任务的时间写法不对（例如间隔不到 15 分钟），草稿会直接去掉这一项；去掉了什么、为什么，小管家在卡片上方那句话
里告诉你。卡片上只有能执行的内容。

想改草稿时，直接在卡片上改，或者对小管家说怎么改：它会请你作废这张，再拟一张新的。一次只出一份提议。

## 新员工卡片上的各项

| 位置 | 内容 |
|---|---|
| 顶部 | 头像、名字、头衔；基于角色模板拟的，写「基于模板：××」 |
| 名字与头衔 | 可改。名字最多 80 字，头衔最多 120 字 |
| 人设与风格 | 性格语气、工作守则、口头约束，可改 |
| 工作指令 | 职责描述（必填，1–1000 字，员工就按这段话干活）与补充指令（最多 1000 字），全文显示，可改 |
| 模型与技能 | 模型只读（建好后在员工页上换）；技能可以逐个移除 |
| 应用 | 要给它的应用，按名字列出，可以逐个移除。能直接给的确认后就给；要管理员批准的会替你提申请；要先连接账号的，结果里会有连接按钮 |
| 定时任务 | 每条的标题或时间，可以逐个移除 |
| 也给它招聘与组群能力 | 勾上，新员工也能替你起草招人和组群；默认不勾 |
| 底部 | 名额提示「这是第 N / M 个员工」；名额满时写「员工名额已满」，「确认创建」不能按，并给「升级套餐」入口 |
| 按钮 | 「作废」「确认创建」。名字或职责描述为空时不能确认 |

新员工默认只有你自己能用（私有）。

## 改员工、组群、调群的卡片

- **改员工**：只列要改的项，每项「改前（删除线）→ 改后」；新加的技能、应用、定时任务直接列出，收回的应用和删掉的
  定时任务带删除线。这张卡片不能就地编辑，要改请让小管家重拟。按「确认修改」执行。
- **组群**：群名可改；成员按回答顺序排成一行，每位都有「上移」「下移」按钮调整顺序。按「确认建群」执行。组群只用
  已有员工：需求里有对不上的角色时，卡片下方列出缺的角色，每个带「先去招 ××」按钮，按下等于对小管家说「先帮我招一个
  ××」——招人和建群是两份提议，各自确认。
- **调群**：群名「改前 → 改后」、加进群的、移出群的、原来的顺序与新顺序。只有群的发起人能调，群里至少留 2 位员工。
  按「确认调整」执行。

卡片右上角是状态：等你确认、正在执行、已完成、部分完成、已作废、已过期。作废和过期的卡片变灰，不能再按。

## 确认之后

卡片变成逐项结果，每一步写做成了什么：

- **✓**：做成了；
- **已转申请**：这个应用你自己给不了，已经替你向管理员提了申请，批准后才有；
- **需要先连接**：这个应用要先连接账号，旁边有「去连接」；
- **失败**：这一步没做成，原因照写。

**这些状态只在确认之后的结果里出现，草稿卡片上没有。** 应用给不给得了、连没连接，按你确认那一刻的权限和连接来定，
所以结果才是准的。

有失败的步骤时，卡片上有「重试失败的步骤」：只按草稿里的内容把失败的几步再做一遍，已经做成的不会重做（已经建好的
员工不会回滚，也不会再建一个）。结果下方有「打开员工」或「打开群聊」。

确认之后跟小管家说一声（例如「确认了」），它会读这份提议的结果再接着说。它只有读到「已执行完」时才会说建好了、改好了。

## 谁能用

- **小管家默认有。** 每个人的小管家（「我的分身」）自带「招聘与组群」，不用去插件页勾。
- **别的员工默认没有。** 要让某位员工也能替你起草，到这位员工的「技能与应用」（个人版是「它能做什么」）里打开
  「招聘与组群」，按员工逐个打开；招新员工时也可以在卡片上勾「也给它招聘与组群能力」。
- **收回之后不会被加回来。** 你从小管家那里收回了这组工具，之后不会再自动给它；要用时自己再打开。管理员对某个工具的
  禁用照常生效。

## 谁能确认

只有提出需求的那个人能确认、作废、重试。员工自己只能起草，执行一律以你本人的身份、在你登录时发生，并且按执行那一刻
重新检查名额、你能给的应用和技能、模型、群成员和群发起人，不信任草稿。

同一工作区里能看到这段对话的其他人，只看到一行摘要，例如「张三的小管家拟了一个新员工：小红书运营（待张三确认）」，
没有任何按钮。别的工作区的人读不到这份提议。

## 限制

- 你在同一段对话里，10 分钟内最多新起草 5 份提议；
- 每人最多 20 份等待确认的提议，超过了要先处理已有的；
- 提议 7 天内没确认就过期，不再执行；
- 套餐的员工名额照常算，确认时会再查一次；
- 名字、头衔、职责描述、指令等的长度上限与「新建员工」相同；定时任务的说明最多 2000 字、标题最多 100 字，间隔至少
  15 分钟，每人启用中的定时任务最多 20 条；
- 起草之后员工或群被别处改过，确认时不执行，提示「内容已变化，请让小管家重新起草」。

## 给部署的人

- 迁移 `0201_staffing_proposals` 新增提议表 `staffing_proposals`，按工作区隔离（RLS）。
- 服务启动时自动添加内置应用「招聘与组群」（`builtin://staffing`），两个版本都有；它不连接任何外部主机、不需要凭据。
- 接口：`GET/PATCH /api/proposals/:id`、`POST /api/proposals/:id/apply`、`/discard`、`/retry`，只认登录的本人；
  群聊另有 `POST/DELETE /api/groups/:id/bots`、`PUT /api/groups/:id/order`。
- 审计：`staffing.proposal_created`、`_edited`、`_applied`、`_partially_applied`、`_discarded`、`_expired`；执行时的
  建员工、授予、申请、定时任务、建群沿用原来的事件，并带上提议 id。
- 端到端检查：CI 的「G6 staffing lifecycle (browser, mocked model)」（`scripts/e2e/staffing-lifecycle.ts`），用模拟
  模型在真浏览器里走一遍招人、确认、建群。
