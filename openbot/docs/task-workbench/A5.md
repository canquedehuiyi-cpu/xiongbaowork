## 为什么 5xx 那一行不能出现「请稍后重试」

中继的 fallback 文案暴露了 r1 的一处违约：r1 对所有失败分支都渲染 act.error.message，而 client.ts 在**非 2xx 且响应体不是 JSON** 时用的正是那句 fallback ⇒ 5xx 会把一句劝人重试的话印在"结果未确认"那一行。结果未知时不能邀请重放——那次写可能已经落库。

r2 的修法按 status 分流：actionFailure() 多返回一个 detail，404／409 带服务端原句（拒绝是确定的），其余 detail 为 null；渲染等价于 failure.label + （有 detail 才加"："加原句）+ （failure.note）。可数证据：act.error.message 在 route 全文命中 2→1（只剩取值那一处）。

判据同批修：② 原先的 500 用例配了 JSON body，恰好绕过 fallback，**对这条禁令测不到**；r2 改成非 JSON 的 500（content-type text/html）并加负断言（提示文字不含「稍后重试」、不含 internal detail），transport 用例补不含「稍后重试」。**实现与判据各自偏弱、合起来才漏过一条被明令的要求**——所以这里也写下方法：新增或转译一条禁令时，先问"哪一条既有用例会因它从绿变红"，答不出就是判据没到位。

## 状态分层

| 返回 | 屏幕上 | 读侧 | 写侧 |
| --- | --- | --- | --- |
| 2xx 成功 | 无提示 | 只 invalidateQueries 一次 ["tasks"]：看板读重发、统计读不动 | 恰 1 次 POST |
| 404 | 「这个任务已经不在那里了」＋服务端原句＋服务端拒绝（404） | 不失效、不重读 | 恰 1 次，不重放 |
| 409 | 「这个任务当前状态不接受这个操作」＋服务端原句＋服务端拒绝（409） | 同上 | 同上 |
| 5xx | 「结果未确认，请刷新任务后核对」＋服务端返回 N（不含「稍后重试」） | 同上 | 同上 |
| 无响应（transport） | 「结果未确认，请刷新任务后核对」＋请求没有收到回应（不含「稍后重试」） | 同上 | 同上 |
