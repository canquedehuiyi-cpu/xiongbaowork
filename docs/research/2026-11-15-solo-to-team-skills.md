# 调研：solo-to-team-skills（一个人带 AI 团队的技能包）

日期：2026-11-15 · 来源：https://github.com/dabingfy-dot/solo-to-team-skills（v0.9 草稿，MIT，884 星，1 次提交）
用户要求（2026-11-15）：「记住他的优势与劣势，采用优势，补齐劣势，融入我们的项目中」。

## 它是什么

四个技能 + 一个登记行模板，流程「提目标 → 分工 → 交接 → 核对 → 判断」：
- `dispatch-accept-verify`：派活登记（只追加不改写）；三步收货「已接下 → 已收到成果 → 已验收」，只有「已验收」或有权限的人「取消」才关单；到点核对、逾期催办与上报、开工/收工清点；「放行后立刻派下一个」。
- `evidence-before-done`：没有证据不准说完成（来自 obra/superpowers）。
- `beginner-ops-writing`：给新手写一步一步的说明。
- `ops-case-notes`：去标识的实际运维案例。
- 支持 Codex、Cursor、CodeBuddy、WorkBuddy、Kimi、通义、DeepSeek，Grok Bot 需手动配置；不带定时器（`hooks: {}`）。

## 优势（要采用的）

1. 抓准了多智能体协作最常见的失败：活派出去没人收、没人验，「等待结束」被当成「交付了」。
2. 三步收货把「接下 / 交成果 / 验过」分开，关单条件明确。
3. 登记只追加不改写，过程可审计；不谎报没人看过的时段。
4. 到点核对、逾期催办、上报，开工/收工清点「还剩 N 件，最早何时到期」。
5. 证据先于完成。
6. 面向新手的说明写法。
7. 自我评估诚实（承认验证有限、无对照实验）。
8. 跨平台、零侵入，装上即用。

## 劣势（要补齐的）

1. 纯纸面流程，全靠模型自觉：会话变长、上下文压缩后登记表最先丢。
2. 没有定时机制：到点核对依赖人或宿主工具提醒。
3. 登记表是纯文本，没有看板、没有通知、没有跨会话的持久状态。
4. 证据由模型自己判断，没有系统层的门。
5. 早期项目（1 次提交、22 个未处理 issue），缺真实使用打磨。

## 熊宝已有、可以承接的部分

任务卡与看板（running / needs_action / awaiting_review / done / failed）、审批底线、员工排班与唤醒、对话侧栏「目标」块（在做）、外部员工（在做）、IM 推送（规划中）。
