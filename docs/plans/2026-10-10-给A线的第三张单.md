## 问题（我在合并后的 main 上实测）

六片全量在新建库上是 **4237 pass / 1 fail**，但那 1 条不是一条普通失败：

```
# Unhandled error between tests
EISDIR: illegal operation on a directory, read   (fd: 3607)
    at applicationDatabaseUrl (/app/server/tests/local-threads.test.ts:99:16)
    at /app/server/tests/local-threads.test.ts:112:33
```

它**不印 `(fail)` 名字**，只在末尾留 `1 fail / 1 error`，并把该文件的 **4 项测试静默吞掉**：
同一分片 A 自己跑是 524 项、我两次跑都是 520 项。

机制是这个文件自己的注释写明的：`createDatabase()` 会 `delete process.env.DATABASE_URL`
（为了 Windows 上不被 Bun 重复解析地址），而 `bun test` 把所有文件跑在同一进程，
所以**任何排在别的 `createDatabase` 之后的文件**都会走到"回退读 `.env`"这一支；
容器里 `new URL("../../.env", import.meta.url)` 指向 `/app/.env`，那里没有这个文件 → 装载期抛。

同类残留还有一条：`attachment-sweeper.test.ts:311`「delete 分批」在**复用库**上必红（期望 4 批实得 3 批），
新库上绿——批数依赖待清扫行数，测试对库内残留敏感。

## 要做

1. **装载期不许依赖会被删掉的环境变量。** 三选一，按代价从小到大：
   a. 在 `tests/support/database.ts` 里把 URL 在模块首次读取时**缓存成导出常量**，各文件用它，
      而不是各自在装载期读 `process.env`；
   b. 回退路径改成**确定的仓库根**（从 `import.meta.dir` 上溯到 `server/` 再取 `../.env`），
      并在容器里保证该文件存在或明确报错说"请传 DATABASE_URL"；
   c. 让 `delete process.env.DATABASE_URL` 只发生在子进程隔离的场景。
   选 a 最稳：它同时消掉"顺序决定成败"这一整类问题。
2. **分片清单入库且确定**：`find … | sort > .scratch/.../server-tests.list` 变成提交进仓库的文件，
   分片按行号区间切，不再依赖 `split -n l/6` 在两次运行间给出不同归属。CI 与本地用同一份清单。
3. **一条自证测试**：新增 `tests/support/load-order.test.ts`，断言"在已有一个 `createDatabase()`
   跑过之后再装载本目录任何测试文件，`applicationDatabaseUrl()` 一类回退分支不得被走到"。
   做不到就在文档里写清为什么。
4. **验收标准（两条都要）**：
   - 新建库上六片全量 **0 fail**；
   - **同一库连跑两次**，两次都 **0 fail**，且每片"Ran N tests across M files"的 N/M 两次完全一致
     （数字一致才算"没有文件被静默吞掉"）。

## 为什么值得单独一张

DoD-1 现在因为这条**不能签**。它不会在 CI 里出现（CI 每次新库、且分片归属固定），
