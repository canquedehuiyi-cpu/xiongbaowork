## WP-1.6 · 后台入口缺平台租户帧（N13）

已实测的证据（不是推测）：
- `openbot/server/src/work/queue.ts` 里 `runAsTenant` 出现 **0 次**；`routines/store.ts:762 dueRoutines` 同样没有帧。
  对照 `devices/queue.ts` 有 6 次 —— 说明这是漏，不是风格。
- 共享库实测：`work_items` 以 `openbot_app` 不设租户查到 **0 行**，`set_config('app.tenant_id','platform')` 后查到 **2 行**。
- 策略文本：`routines` / `work_items` 的 SELECT 是
  `tenant_id = current_setting('app.tenant_id') OR tenant_id='system' OR current_setting('app.tenant_id')='platform'`。

要做：
1. **先把范围查全，不要只修我点名的两处。** 所有"不为某个人运行"的入口都要过一遍：
   例行调度（`routines/sweep.ts` 及其 store 调用：`dueRoutines`/`advanceNextRun`/`routineForFiring`/`insertRun`）、
   群聊后台队列（`work/queue.ts`）、职责引擎（`responsibilities/engine.ts`）、看板回收（`tasks/reclaim.ts`）、
   流水线收尸（`pipeline/reap.ts`，已有帧，确认即可）。判据：入口若不以某个 `session.user.id` 为作用域，就必须显式 `runAsTenant("platform", …)`。
2. 修法照 `devices/queue.ts` 的现成写法，**不要新造机制**。
3. 回归测试（新文件，例如 `tests/unattended-platform-frame.integration.test.ts`）三段都要有：
   a. 以真实租户播一条到期 routine 与一条待处理 `work_items`；
   b. **以 `openbot_app` 连接、不设帧 → 查到 0 行**（证明 RLS 真的在管，也证明这条测试不是假绿）；
   c. 设 `platform` 帧 → 查得到，且 `offerDueRoutines()` / 队列认领在**设帧后**确实把这两条消费掉。
4. 端到端一条：`OPENBOT_RLS_ENFORCE=refuse` ＋ `openbot_app` 连接串起服务，一条到期例行真的被触发、一条群聊轮次真的被认领。

## WP-1.6b · 402 拒绝后留下删不掉的凭据残行（N15）

现象（我独立复跑得到的，非自报）：`server/tests/quota.test.ts:243`
`expect(orphans.length).toBe(0)` 收到 **5**；同一文件在**空库**上 7 pass / 0 fail，在**用过的库**上必红。
差值＝运行次数，说明每次 402 拒绝都留下一行，且测试自己的 `afterAll`（`database.delete(credentials)`，
以 `openbot_app` 身份、受 RLS 约束）**删不到它**。

要做：
1. 先加一条**不受租户作用域保护**的断言：用 owner 连接读 `credentials` 全表行数，
   断言"Free 档被拒后，任何租户下都不该多出行"。当前实现应让它红。
2. 修写入顺序：配额检查必须在任何凭据落库之前完成；若确实需要先行落库，则与拒绝路径同事务回滚。
3. 让测试自己幂等：跑前清干净自己播的行（而不是假设整库为空）。
   **标准：同一套件在同一库上连跑两次都必须是 0 fail**——CI 每次拿新库，掩盖了这类问题，本地不会。
