## 视觉与行为实现

1. 先落共享壳和令牌。以深色背景、左栏与卡面灰阶、细描边、低对比文字、淡绿色主操作、圆角和控件密度为基准。测量后写入 `styles.css` 的既有主题变量。优先复用 Button、Tabs、Select、Dialog、Skeleton、Empty、QueryError、Avatar、PageShell，避免五套重复规则。让现有主题状态和可访问性继续工作。
2. 每页按参考顺序实现默认、有数据、筛选无结果、加载、失败重试、未授权、禁用、表单校验和提交中。背景刷新失败仍展示可用缓存。导航选中、焦点、hover、active、弹窗返回、列表滚动及输入行为应进入截图或自动化断言。
3. 保持现有 Query keys、API、审批、租户、设备、配额和模型调用边界。表格、卡片、指标由我方真实状态或明确的测试 fixture 驱动。IM、流程、插件授权和实际任务触发缺后端契约时，记下入口、缺失契约、可复现证据和剩余工作。保留真实禁用或失败语义，禁止用成功占位消掉差异。
4. 参考图中会变化的头像、用户名、日期、计数、动画用固定 fixture 归一。项目展示素材统一使用本项目品牌。素材许可或受限页面看不到时保留明确替代和待验证项目，并在最终差异表列出。

## 验收门槛

- **截图**。用同一 Chromium 版本、DPR、字体、缩放、主题、合成数据和稳定状态重拍。提交每页每个关键状态的参考图、实现图、差异图和测量表。建议用每通道 8/255 的颜色阈值作像素判定，约定区域内差异像素不超过 1%。主列、卡片、页头、工具栏关键锚点偏差不超过 2 CSS px。动态遮罩须在基线阶段登记。缺失或错位的组件即使全屏比例小也判失败。经同条件复测后再给出 1:1 结论。
- **交互**。用仓库已有 Bun 与 Playwright Core 基础验证键盘焦点、加载/错误、筛选与排序、切换标签、表格/卡片/泳道、提交校验、详情、页面刷新和深链接。用真实 UI 点击路径验证已有 API 调用和结果呈现。测试从专用 fixture 获取身份及数据，外部模型、真实 IM 和真实生产动作单独取证。
- **回归**。在 `openbot` 按锁文件执行 `bun install --frozen-lockfile`，运行 `bun run --cwd app typecheck` 和 `bun run --cwd app build`。沿用主仓 app 测试与 CI 入口，分别记录测试总数、失败数、构建结果、浏览器实测结果和隔离环境。依赖或运行时被阻断时保留原始错误，修复后重跑对应门槛。
- **交付**。给出参考页与我方路径、实现提交、实测证据、允许差异和剩余缺口。视觉、交互、运行时分别验收。正式部署和生产验收另列。
