## 0. 三条硬规则

1. **每个路径只有一个主人**。下表之外的任何文件你都不改；要改就停下来提需求给那个主人。
2. **每个轨道一个 git worktree + 一个分支 + 一个数据库 + 一组端口**。绝不共用运行态。
3. **跨轨只经两种接口**：HTTP 响应字段形状（写进 `openbot/docs/contracts/*.md`）与 git（rebase 后单一顺序合并）。不共享未提交的工作区状态。

## 4. 合并顺序与冲突处理

1. 合并序 **A → B → C**（A 的响应字段是 C 的前置；B 的 CI 断言要看到 A/C 的结果才有意义）。
2. 每个 WP 一个分支一次 PR，PR 描述写"问题 → 改动 → 证据（命令输出/截图路径）"。
3. 后开跑的轨在合并前 `git rebase origin/main`；**冲突若落在别人名下路径，放弃你那份改动并去问主人**，不要替别人合并。
4. 红灯比对用**失败名字多重集差集**，不比总数（本项目的既有纪律）。
