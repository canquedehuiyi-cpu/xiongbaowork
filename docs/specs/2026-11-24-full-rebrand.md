# 彻底去掉上游品牌 + 迁到干净新仓库：设计稿

状态：用户 2026-11-24 确认（「设计稿没问题，按这个执行」）。摸底：`docs/specs/2026-11-24-full-rebrand-recon.md`（下称「摸底」）。

## 1. 目的与为什么

用户要求：**任何智能体或人探查熊宝的源码、前后端、安装包、镜像、提交历史，都看不出它是由 OpenBot 改出来的**；同时保留以后从上游拿更新的可能。

用户已定（2026-11-24）：
- 方案 A：全部改名；同步上游时先用同一张改名表把上游代码自动改名再合并；已在外面运行的名字先新旧双认、再删除。
- 新建干净私有仓库（单个首次提交，不带历史）：`canquedehuiyi-cpu/xiongbao`（用户已建）。旧仓库 `xiongbaowork` 由用户改私有并归档。
- 现网只有用户自己的：京东云一台单容器服务器、用户自己电脑上的设备端与浏览器扩展。没有客户部署、没有 Helm 用户、没有托管 Bot 镜像在外面跑。

## 2. 目标、非目标、反目标

**目标（验收口径）**
1. 新仓库全部文件（含文件名、目录名、提交信息、作者信息）不分大小写搜不到 `openbot`、`open-bot`、`open_bot`、`open.bot`；唯一例外见目标 4。
2. 构建产物（前端包、扩展包、设备端安装包、runner、容器镜像的文件系统与默认配置、启动日志）同样搜不到。
3. 运行中的系统对外暴露的东西（HTTP 头、错误码、环境变量名、浏览器存储、数据库对象名、进程名、日志、指标属性）同样搜不到。
4. **许可证例外（法律要求，不能去掉）**：MIT 要求随代码保留原版权声明与许可文本。新仓库只在一个文件（`THIRD-PARTY-NOTICES.md` 或 `LICENSE` 的第三方段）里保留 `Copyright (c) 2026 CopilotKit` 与 MIT 原文，**不出现 OpenBot 这个词**，也不写「derived from …」之类说明。这一点不是法律意见，建议用户自己确认。
5. 依赖包 `@copilotkit/*` 是公开第三方库，保留（换掉等于换技术栈，不在本项目范围）。除依赖声明与许可证文件外，`copilotkit` 字样也要清掉（§12 决定 3）。

**非目标**
- 不改 `@copilotkit/*` 依赖；不改第三方库内部的字符串。
- 不追求让「看过上游代码的人逐行比对」也认不出（代码结构本身相似，这无法也不必隐藏）。

**反目标（做成这样就算失败，哪怕名字都改了）**
- 京东云现网数据丢失或解不开：已存凭据、审批的精确输入对象、对话历史、线程映射任何一项读不出来。
- 升级当天服务长时间不可用（目标：与普通升级一样，一次重启）。
- 改名后测试被放宽、跳过或删除。
- 上游同步彻底失去（目标：仍能对上游仍公开的目录做同步，见 §6）。

## 3. 关键事实（来自摸底，决定了做法）

- 品牌字样：全仓 2 472 个文件、30 747 行（`archives/` 294 个文件不进新仓库）。`@openbot/*` 788 行；`OPENBOT_*` 232 个名字（部署者会设的 48 个）；路径含 openbot 58 个。
- **上游已不公开后端**：上游 main 在 2026-11-11～13 之间移走了 `server/ worker/ runner/ toolkit/ charts/ supervisor/ agent-computer/ docker/` 等。熊宝这些目录以后没有上游可同步，按熊宝为准。仍有同步价值的：`app/ extension/ desktop/ shared/ mobile/ agent-*/ api/ tokens/ management-agent/ docs/`。
- 已落进数据的名字（摸底 §2.4、§2.5、§3）：数据库超级用户/库 `openbot`、角色 `openbot_app`/`openbot_role_writer`、约 20 个 `openbot_*` 触发器与函数、GUC `openbot.audit_retention_days`、NOTIFY 通道、审批精确输入的版本串（同时是列值与 CHECK 约束）、凭据加密 AAD、7 个签名/派生域串、对话历史里的事件名与标记、租户包 id `openbot`（决定新线程 id 前缀）、扩展 IndexedDB 库名与策略键、设备端旧进程名、默认皮肤值。

## 4. 做法总览（已选方案 A，分四段）

因为现网只有用户自己一套，采用**「过渡版一次性迁数据 + 下一版删干净」**，不做长期双认：

| 段 | 版本 | 内容 |
|---|---|---|
| 一、代码层改名 | 合入 main，不单独发版 | 只改「不落数据、不出进程」的名字：标识符、包名 `@openbot/*`→`@xiongbao/*`、文件与目录名、注释、测试、CI、文档。纯机械，分区域多个 PR |
| 二、对外名字双认 | 与段三同一个发版 v0.2.16 | 环境变量、HTTP 头、错误码、扩展消息/策略键/存储、设备端名字：**写新名、读新旧两个**；旧名出现时启动日志警告 |
| 三、数据一次性迁移 | v0.2.16（过渡版） | 启动迁移把数据库、加密数据、历史记录全部改成新名（§5）；迁移幂等、可重跑；迁移前自动备份数据库 |
| 四、删除一切旧名 | v0.2.17（清理版） | 删除双认与迁移代码，旧名在源码与产物里归零；护栏改成「出现即失败」；然后导出到新仓库（§7） |

京东云升级顺序：先升 v0.2.16（迁移在启动时完成，健康检查通过、核对数据可读），用户把 `.env.delivery` 里的 `OPENBOT_*` 改成 `XIONGBAO_*`（我给一键脚本），重装/升级自己电脑上的设备端与扩展到 v0.2.16；再升 v0.2.17。

## 5. 数据迁移逐项做法（v0.2.16）

| 对象 | 做法 | 失败时 |
|---|---|---|
| 超级用户与库 `openbot` | 启动脚本检测到旧名：连 `postgres` 库执行 `ALTER ROLE openbot RENAME TO xiongbao`、`ALTER DATABASE openbot RENAME TO xiongbao`，同步改连接串文件。SCRAM 口令与用户名无关，不重设 | 不改任何东西、启动失败并打印原因（数据不动） |
| 角色 `openbot_app`、`openbot_role_writer` | 新迁移 `ALTER ROLE … RENAME`，启动脚本里 `ALTER ROLE … PASSWORD` 改用新名 | 同上 |
| 历史迁移 SQL 里的旧名 | **v0.2.17** 压缩迁移（§12 决定 4）：把 `server/drizzle` 与 `server/recovery` 的全部历史迁移合成一份「当前结构」的基线（新名），老库靠 v0.2.16 的迁移走到同一结构；新装库直接用基线。迁移表按基线重新记账 | 基线与老库迁移后结构不一致 → 由「结构比对测试」拦住（新装库与迁移后的老库 `pg_dump --schema-only` 必须一致） |
| 触发器/函数 `openbot_*`、GUC、NOTIFY 通道、迁移锁名 | 新迁移 `ALTER FUNCTION/TRIGGER … RENAME`；服务端 SQL 同步改名；GUC 读新名，迁移把旧设置值拷过去 | 同上 |
| 审批精确输入版本串 `OPENBOT_*_V1`（列值 + CHECK） | 新迁移：放宽约束接受新旧值 → 用新版本串**重写存量行**（这些串是格式标签，不参与密钥派生的部分直接改；参与 AEAD 关联数据的部分解密后用新串重新加密）→ 收紧约束只认新值 | 有一行失败就整体回滚，服务继续用旧值启动并报错（v0.2.16 仍认旧值） |
| 凭据加密 AAD `openbot.vault.credential.v2` | 加新 kid `k2`（新 AAD）；迁移逐行「旧 AAD 解密 → 新 AAD 加密」；全部成功才提交 | 同上 |
| 签名/派生域串（agent-run、bearer、自动化钩子、电脑令牌、遥测、web-bot-auth） | 全部换新。运行断言不重签：v0.2.16 迁移前置检查要求没有在途审批与续跑（§12 决定 5）。自动化钩子签名、web-bot-auth：换新，现网用到的由用户重新配置（§12 决定 1） | — |
| 对话历史里的事件名、标记、工具 id | 迁移批量重写 JSON 里的旧名为新名（只改这些字面量，不碰其他内容）；读取端 v0.2.16 两个都认 | 回滚，继续认旧名 |
| 租户包 id `openbot` | 改成新 id；`DEPLOYMENT_ID` 为空时现网会改变新线程 id 前缀——迁移在数据库里记下旧部署名，v0.2.16 起显式沿用旧的**摘要值**（只存摘要，不存旧名明文），新线程 id 前缀不变 | — |
| 扩展：IndexedDB `openbot-recorder`、策略键、消息类型 | **换新扩展 id、签名密钥与原生宿主名**（§12 决定 2）；用户卸旧装新，旧扩展本地数据不迁；服务端认可的扩展 id 同步改 | — |
| 设备端：旧进程名清理、数据目录名 | 数据目录在 v0.2.16 改名（启动时移动目录）；旧进程清理在 v0.2.17 删除 | 移动失败继续用旧目录并报警 |
| 默认皮肤值 `openbot`、浏览器存储键 | 读到旧值映射成新值并写回 | — |
| 发布记录 `images.openbot`、镜像名 | v0.2.16 起只写 `images.xiongbao`；`mirror-release.yml` 改读新键（已发安装器只有用户自己的，重装即可） | — |
| Helm chart `charts/openbot` | 无人在用：改名为 `charts/xiongbao`，标签前缀改新名 | — |

**实施前必须先确认的现网事实**（实施计划的第一个任务，在京东云上跑只读命令）：`.env.delivery` 里有哪些 `OPENBOT_*`；数据库里实际的角色/库名；是否用过自动化钩子签名、web-bot-auth、OpenTag 对端、Intelligence 学习容器（用过就要加迁移或重新配置步骤）。

## 12. 审读后的补充决定（2026-11-24）

### 用户决定
1. **第三方已登记旧名**（Composio/Arcade 共享账号身份 `openbot-deployment:…`、OpenTag 路径 `/openbot/membership|deliver`、Intelligence 学习容器 id、web-bot-auth 派生密钥）：全部改名；现网用到的项升级后由用户重新连接（我给步骤），不保留旧名。
2. **浏览器扩展**：换新扩展 id 与签名密钥、原生宿主名改新名；用户卸载旧扩展装新扩展，旧扩展本地录制数据不迁（接受丢失）。新私钥只存在发布用 secret 里。
3. **清理范围扩大到 CopilotKit 非依赖痕迹**：删除 `desktop/` 整个目录（上游整栈安装器，不交付；用户用的是自己的 `desktop-device/`）；CopilotKit 自家云服务接入（Intelligence、`copilotkit.ai`、`api.intelligence.copilotkit.ai`、`COPILOTKIT_*`/`CPK_*` 环境变量、`ai.copilotkit.*` 标识）现网没在用的删除，在用的改中性名字并列出给用户。保留的只有 `@copilotkit/*` 依赖包名与许可证版权行。验收搜索词因此扩大为 `openbot|open-bot|open_bot|open\.bot|copilotkit`（不分大小写），只在依赖声明（package.json 的依赖名、lockfile、`node_modules` 导入路径）与许可证文件里放行。

### 控制方定（可推翻）
4. **迁移基线化放在 v0.2.17**：历史迁移 SQL（`server/drizzle`、`server/recovery`）在 v0.2.17 压成一份新名基线；v0.2.17 启动时先导出现网 `--schema-only` 与预期结构逐项比对，完全一致才把 `drizzle.__drizzle_migrations` 改写为基线记录（单事务），不一致拒绝启动并打印差异；新装库直接走基线。结构比对测试除 CI 库外，用京东云现网导出的结构（实施时由用户在服务器上导出 `--schema-only`，不含数据）做一次。外接库、开发库、e2e 库：现网没有外接库；开发与 CI 库每次新建，不需要升级路径。
5. **在途项先清空**：v0.2.16 迁移前置检查：有待审批的请求、未完成的续跑、未过期的运行断言时拒绝迁移，提示用户先处理完再升级；因此不重算审批摘要与续跑摘要、不重签运行断言。
6. **语义键随迁移改名**：`plugin_grants.granted_by/updated_by` 的 `openbot:staffing-default|personal-defaults|always-on`、记忆默认值键 `openbot:defaults:…` 等「代码靠它判断」的标记，在 platform 身份下随 v0.2.16 迁移改成新名（已核对哪些表有行守卫，迁移走 platform 帧）。
7. **审计记录与用户内容不改**：`audit_events` 保持只追加，不拆保护，旧记录原样留在库里；用户消息、模型回复、记忆正文、导入的技能等自由文本不改。目标 3 的口径相应限定为「系统写出的名字」，库里历史数据不在源码与产物验收范围内。
8. **回滚**：v0.2.16 迁移前自动 `pg_dump` 到服务器本地 `/opt/xiongbao/backup/pre-rebrand-<时间>.dump`（权限 0600），保留到 v0.2.17 升级稳定后由用户删除；迁移成功后的回滚 = 恢复该备份 + 回 v0.2.15 镜像，丢失升级后新写的数据。v0.2.16 观察至少两天再发 v0.2.17。
9. **审批精确输入两表**：代码无写入方；R0 在现网核对行数，为 0 则只改约束与常量，不做重加密；不为 0 再请用户决定。
