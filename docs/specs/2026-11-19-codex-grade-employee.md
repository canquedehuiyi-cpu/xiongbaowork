# 修复方案：让熊宝员工达到 Codex 级工作能力

状态：**草案，等用户拍板**（2026-11-19）。基线：`main` e5e3f316（v0.2.13 之后，含 WP-3.1 / WP-3.2）。

## 0. 用户反馈与目标

用户实测（2026-11-19 原话）：「员工智能体工作一般就停；整个输出感觉就跟在线版的 deepseek 对话机器人一样，根本不是跟 codex 一样的工作型智能体，输出、交互、推理都没有；每个员工没有子代理。」「我要的是一个跟 codex 一样能力的数字员工的能力。」

目标——员工在一次对话里表现出 Codex / Claude Code 那样的五个特征：

| 特征 | 现在 | 目标 |
|---|---|---|
| 持续干到完成 | 对话轮 8 步就被强制收尾，中文「让我先…」类说完就停 | 一轮能跑 40 步以上，触顶可「继续」，许诺了就得做 |
| 先计划、逐项推进 | 没有计划/待办工具 | `update_plan` 待办清单置顶，逐项打勾 |
| 看得见的思考 | DeepSeek 思考模式被全局关闭，界面无思考块 | 思考模式默认开，界面可折叠「思考」块实时流出 |
| 看得见的动作 | 工具行有（WP-3.2 已加耗时/退出码），默认折叠 | 保留并默认展开当前在跑的那一行 |
| 子代理 | 有 `run_subagent`，但提示词劝退、界面藏在一行「子任务」里 | 多步任务主动委派，界面单独显示子代理卡片与实时状态 |

## 1. 根因（只读诊断，均在 `xiongbao/` 下）

1. **思考被关**：`server/src/models/deepseek-thinking.ts:22-27,77-87`（启动时 `server/src/index.ts:2408` 装上）给发往 `api.deepseek.com` 的请求强制加 `thinking:{type:"disabled"}`，除非 `DEEPSEEK_THINKING=enabled`。原因：带工具时 DeepSeek 要求把上一轮的 `reasoning_content` 原样回传，而线程历史不存它，开了会 400。部署级模型走 CopilotKit `resolveModel`（openai 提供方），`reasoning_content` 不解析；前端只有一行「思考中」（`app/src/…/chat-transcript.tsx:458`），全仓无推理渲染。
2. **8 步就收尾**：`server/src/copilot.ts:1388` `TOOL_STEPS = 8`（有搜索工具 +2，`:1324-1326`）；无人值守轮是 48（`toolkit/src/copilotkit/last-step.ts:77`）。到最后一步 `last-step.ts:150-156` 置 `toolChoice:none` 并注入 `LAST_STEP_NOTICE`（`shared/run-notices.ts:17`）要模型「现在作答、说明没做完什么」。之后没有续跑，界面也不提示——用户看到的就是「自己停了」。
3. **说完就停**：一步没调工具就结束本轮；只有 `unkeptPromise` 判为失诺才追问，最多 `MOST_NUDGES = 2`（`last-step.ts:61`）。WP-3.1 的中文词表（`toolkit/src/copilotkit/unkept-promise.ts:86-87`）漏了 DeepSeek 最常见的「让我…」「我将…」「我先…」「我来…」「首先…」「下面开始…」「然后我会…」；以问句收尾（「需要我继续吗？」）一律放行。
4. **没有计划**：全仓无 todo / plan 类工具；`shared/bot-prompt.ts:551-561` 的 HOW_TO_WORK 只讲取数与重试；员工角色卡只有一两句人设。
5. **子代理被劝退、看不见**：`run_subagent` 对人发起的对话默认可用（`server/src/index.ts:3747-3762`，与套餐无关，每轮最多 5 个，不可嵌套），但工具描述（`server/src/agents/subagent.ts:175-180`）、提示词（`shared/bot-prompt.ts:337-352`）和租户包 `skills.yaml`（#676 改过）都先强调「比自己做慢、只在…时用、优先串行」；前端折叠成一行「子任务」（`app/…/tool-activity.tsx:175`）。
6. **卡流看门狗**：`config.ts:1769-1772` 默认 0（关）；且只包远端 AG-UI（`copilot.ts:2629`），对内置员工不起作用。不是「中途停」的主因。

WP-3.1（#697）已补中文句末标点、子代理交还熔断、看门狗环境示例；WP-3.2（#698）已补工具行实测事实与实时耗时。**以上 1–5 都还没解决。**

## 2. 分期修复

每期独立可验收；服务器改动测试全绿即推，界面改动先截图给用户确认再推（项目规矩）。

### 期一「不再半路停」（小，约 1 个 PR）
- 对话轮步数 `TOOL_STEPS` 8 → **40**（与无人值守 48 同量级），保留墙钟与 token 预算兜底。
- 触顶时发明确事件；界面在回答末尾显示「已用完 40 步 · 继续」按钮，点了带上下文续一轮（界面，要截图）。
- 中文失诺词表补齐上面那批开头，各加回归用例；`MOST_NUDGES` 2 → **4**。
- 验收：真 DeepSeek 跑一个约 15 步的任务（见 §3），不中途停。

### 期二「先计划、逐项推进」（中，约 2 个 PR）
- 新增工具 `update_plan(items: {text, status: "pending"|"in_progress"|"done"}[])`，服务器侧授予所有员工（员工级工具权限仍可关）；计划存在本次 run 上，随消息流推给前端。
- HOW_TO_WORK 加一段：多步任务先建计划 → 一次只做一项 → 做完打勾 → 全部完成再总结；计划里还有未完成项时停下，按失诺追问一次。
- 界面：对话顶部置顶的待办清单，实时打勾（要截图）。

### 期三「看得见的思考」（大，约 3 个 PR）
- 线程历史保存 assistant 的推理内容；同一次 run 的工具循环里按 DeepSeek 要求原样回传 `reasoning_content`。
- DeepSeek 改走 OpenAI 兼容提供方（`@ai-sdk/openai-compatible` 或专用 deepseek provider），推理作为 reasoning 部分流出 → AG-UI 推理事件。
- 回传跑通后把 `DEEPSEEK_THINKING` 默认改为开启（保留 `disabled` 开关）。
- 界面：可折叠的「思考」块，流式显示，默认收起只露首行（要截图）。
- 成本提示：思考模式 token 与时延上升，需用户决定是否默认开（见 §4）。

### 期四「子代理」（中，约 2 个 PR）
- 改写 `run_subagent` 描述、`bot-prompt` 子代理段、租户包 `skills.yaml`：多部分任务（调研 / 撰写 / 校验）鼓励各派一个子代理并行；保留每轮上限与不可嵌套。
- 界面：子代理单独成卡——任务名、实时状态、耗时、可展开看结果（要截图）。
- 后续可选：员工上配置命名子代理（如「研究员」「校对」），不在本期。

### 期五 验收与对比
- 在 `model-e2e.yml`（只有 `workflow_dispatch`，key 在 Environment `model-e2e`）加一个真模型「工作型任务」作业：例如「调研三家竞品，写对比报告并存成文件」。记录：总步数、是否中途停、是否出计划、是否用子代理、是否有思考块、产物是否可打开。
- 修复前后各跑一次，结果写进 `docs/acceptance/`。

## 3. 验收标准（全部满足才算达标）
1. 15 步以上的任务一轮内做完或明确触顶并可「继续」，不出现无提示的半路停。
2. 多步任务先出计划，界面清单逐项打勾。
3. 界面能看到思考块（期三完成后）。
4. 三段以上可并行的任务至少派出一个子代理，界面单独显示。
5. 全部 CI 绿，main 既有断言不改（如需改，先报用户）。

## 4. 需要用户拍板
1. **谁来做**：Qoder 正在做 WP-3.x（WP-3.3 已排上）。本方案可交 Qoder 按期执行，或由 Claude 执行；两边不能同时动同一批文件。
2. **思考模式默认开还是按员工开**：开了效果像 Codex，但 DeepSeek 费用和等待时间会上去。建议：默认开，员工设置里可关。
3. **对话轮步数上限**：建议 40；以及触顶是只给「继续」按钮，还是服务端自动续 1 轮。
4. **顺序**：建议 期一 → 期二 → 期四 → 期三（前三期改动小、观感提升最快；期三最大）。
