# 设备端桌面操控（数字员工操控本机应用 · 子项目二）

日期：2026-11-07
状态：草稿，待用户审阅
上游：
- 子项目一「本机 MCP 桥接」已合入，见 `docs/specs/2026-11-07-device-mcp-bridge.md`。
- 用户已定的方向：
  - 覆盖「任意应用」；
  - 路线 A，即设备端常驻 PowerShell 助手，配合 .NET UI Automation；
  - 结构树和截图两种方式都支持：结构树是基础，模型能看图时再附截图；
  - 按会话授权：员工第一次操作桌面时审批，之后在有效期内可以连续操作；电脑上显示醒目提示，用户随时可以叫停；发送、删除、付款这类操作仍然单独审批。

## 1. 目标与范围

**目标**：员工能像人一样操作主人 Windows 电脑上的任意应用，包括：找到窗口、读到窗口里的内容、点击、输入、按快捷键、启动和切换应用。

**成功标准**：
1. 员工能用 `computer_desktop_windows` 列出可见的顶层窗口，返回标题、进程名和窗口编号。
2. 员工能用 `computer_desktop_snapshot` 读取某个窗口的界面结构树。每个可操作控件有一个编号，附带类型、名称、值和是否可用，深度和节点数有上限。纯文字模型（DeepSeek）凭这棵树就能定位「记事本的编辑区」「保存按钮」。
3. 员工能按编号点击、在控件里输入文字、按快捷键；必要时可以按坐标点击，但必须先截过图。
4. 第一次桌面动作会弹出「桌面会话」审批。批准后 15 分钟内同一个员工可以连续操作，每次操作都会续期，但总时长不超过 60 分钟。会话期间屏幕顶部有置顶提示条「熊宝员工正在操作你的电脑 · 按 Ctrl+Alt+Esc 或移动鼠标即可停止」。用户一动鼠标、一按停止键，会话就立刻结束，正在执行的动作中止，并且必须重新审批。
5. 点击名称匹配「发送、删除、付款、提交、确认支付」这类敏感词的控件，或者按 Enter 提交，即使在会话内也要单独审批。
6. 模型能看图时，`computer_desktop_snapshot` 附带窗口截图（PNG，长边最多 1280 像素）；不能看图时只返回结构树。
7. 已经用 WIN1 探针在 CI 的 Windows 机器上实测过：列窗口、读记事本的结构树、输入文字、读回内容，全部能跑通。

**不做的**：
- macOS 和 Linux；
- 录制与回放；
- OCR（看不懂图的模型也拿不到图里的文字）；
- 跨用户会话和 UAC 提权窗口：会话 0 和更高完整性级别的窗口操作不了，要明确报错；
- 多显示器上的坐标换算，第一期只支持主显示器。

## 2. 方案（已定：路线 A）

**常驻 PowerShell 助手**：
- runner 启动 `powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command -`，通过标准输入加载一段内置的 C#（`Add-Type`，引用 UIAutomationClient、UIAutomationTypes、System.Windows.Forms、System.Drawing），之后按行收发 JSON 指令。
- 第一次使用约 2 秒，之后每个动作约 100 毫秒。
- 进程闲置 10 分钟退出，runner 退出时一并结束。

**C# 部分只做原语**：
- `windows`：列出可见的顶层窗口；
- `tree`：从一个窗口句柄开始，用 TreeWalker 的 ControlView 遍历，深度不超过 12，节点不超过 800；
- `invoke`：优先走 InvokePattern，不支持就模拟点击控件中心；
- `setValue`：优先走 ValuePattern，否则先聚焦再 SendInput 逐字输入，Unicode 也能输入；
- `keys`：SendInput 组合键；
- `focus`：SetForegroundWindow，配合 AttachThreadInput 技巧；
- `screenshot`：用 PrintWindow 截指定窗口，失败时退回截屏幕区域；
- `launch`：Process.Start；
- `cursor`：读取光标位置，用来检测用户有没有动鼠标。

**控件编号**：
- 每次 `tree` 生成一个新的快照号。控件编号的形式是 `快照号:序号`，助手在内存里保存「编号 → RuntimeId 或元素」的映射。
- 编号来自过期的快照时直接拒绝，提示「界面已变化，请重新读取」。这和浏览器 snapshot 的做法一致，见 `runner/src/browser.ts`。

## 3. 组成部分

| 位置 | 内容 |
|---|---|
| `runner/src/desktop/helper.cs` | 内置的 C# 源码，作为字符串资源打包 |
| `runner/src/desktop/host.ts` | 启动并管理助手进程，按行收发 JSON，每次请求有超时（默认 15 秒），负责闲置回收和结束整棵进程树 |
| `runner/src/desktop/session.ts` | 设备端的会话守卫：只有收到服务器下发的会话令牌，并且令牌没过期、用户没叫停，才执行动作；每 250 毫秒检测一次鼠标是否被移动，以及停止热键 |
| `runner/src/execute.ts` | 新增动作 `desktop.windows`、`desktop.snapshot`、`desktop.click`、`desktop.type`、`desktop.key`、`desktop.launch`、`desktop.focus`，非 win32 平台一律拒绝 |
| `desktop-device`（Tauri） | 置顶提示条窗口；全局热键 Ctrl+Alt+Esc 通知 runner 停止 |
| `server/src/computer/headless-tools.ts` | 新增 `computer_desktop_*` 工具，只在设备模式、员工主人本人的运行里提供（与 MCP 桥接的 I2 规则一致） |
| `server/src/computer/gateway.ts` | 走现有设备网关；新增「桌面会话」审批（toolRef `computer_desktop_session`），批准后服务器生成短期会话令牌，随每个桌面动作下发 |
| `server/src/approvals/policy.ts` | 新增两条底线：会话外的任何桌面写动作一律先审批；敏感控件和 Enter 提交即使在会话内也要单独审批；团队「电脑上运行命令」上限同样作用于桌面写动作 |
| 网页 | 员工权限页新增「操作桌面」；审批卡片展示窗口标题和控件名称 |

## 4. 安全与放权

1. 只能操作员工主人本人的设备，并且只在主人本人发起的运行里可用。
2. 读操作（windows、snapshot）不需要会话，但截图和结构树都会进入模型上下文。所以列窗口和读窗口也要经过员工级开关，默认开启，可以设为「从不」。另外，读取标题含「密码」「银行」「支付」的窗口要先审批，这个关键词表可以在团队设置里改。
3. 写操作（click、type、key、launch、focus）都要在有效的会话内执行。会话令牌由服务器签发，设备端校验。叫停时会话在设备端立即作废，并上报服务器。
4. `type` 动作的内容如果像密码，例如目标控件是密码框（IsPassword），一律拒绝，改用现有的 `computer_request_secret` 流程，让人自己输入。
5. 审计：每个桌面动作写入现有的审计行，记录窗口标题、控件名和动作类型；不记录输入内容，只记录长度。

## 5. 出错处理

| 情况 | 返回给员工 |
|---|---|
| 非 Windows 设备 | 「这台设备不是 Windows，暂不支持桌面操作。」 |
| 窗口不存在或已关闭 | 「找不到这个窗口，请重新列出窗口。」 |
| 控件编号过期 | 「界面已变化，请重新读取窗口。」 |
| 提权窗口（UIPI 拒绝） | 「这个窗口需要管理员权限，员工无法操作。」 |
| 用户叫停 | 「用户已停止桌面操作，需要重新获得授权。」 |
| 助手启动失败 | 「桌面助手启动失败：…」，附上 stderr 尾部 |

## 6. 分期与验收

- **第 1 期，只读**：`desktop.windows`、`desktop.snapshot`（结构树和截图）、对应的服务器工具，加上 WIN1 探针（打开记事本、读出编辑区控件）。同时补测浏览器能力在 Windows 真机上的表现。
- **第 2 期，操作**：click、type、key、launch、focus；会话审批、令牌、置顶提示条、热键和鼠标叫停；WIN1 探针实测在记事本里输入并读回。
- **第 3 期，细化**：敏感控件的单独审批、坐标点击、按模型能力附带截图、团队关键词表。
- **真机验收**（在用户的 Windows 设备上）：
  1. 记事本：写一段话并保存到 `C:\xiongbao-test2\note2.txt`；
  2. 计算器：算 12×34；
  3. 资源管理器：打开一个文件夹并读出文件列表；
  4. 微信（UIA 覆盖有限）：只验收结构树加截图能读到会话列表；发消息必须单独审批。

## 7. 风险

- **UIA 覆盖不全**：微信、部分游戏、Electron 应用的结构树不完整，只能靠截图加坐标，也就是第 3 期加看图模型。纯文字模型对这类应用能力有限，需要在界面上说明。
- **抢鼠标**：员工操作期间用户如果同时在用电脑，会互相干扰。所以叫停条件是「用户一动鼠标就停」。
- **安全软件误报**：模拟输入可能被杀毒软件拦截。未签名安装包更容易触发，所以 D3 代码签名的优先级要提高。
