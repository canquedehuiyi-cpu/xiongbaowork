# 召唤员工：会话从空开始、翻卡召唤、按员工安装技能

日期：2026-11-14 · 状态：待用户确认

## 为什么做

熊宝做的是「一人公司」（OPC）：一个人带一队数字员工把公司开起来。预设员工不是一上来就在岗的人，而是**等着被招来的员工**。用户召唤谁，谁才进到自己的会话里；召来以后，用户再给他一个个装技能、装插件、选模型。

现在的做法跟这个相反：
- 新用户一登录，会话列表里已经有「通用助手」「研发流水线」等会话，还有「我的分身」；
- 包里预设的技能在开通时就自动装到各个员工身上，看起来「默认全装了」；
- 预设员工没有配熊宝形象，显示的是按名字生成的圆球；
- 员工会话页顶部的大头像卡片是消息列表的第一条，聊多了就被顶走。

## 用户说过的（原话或原意）

- 「会话里没有，必须在员工列表进行召唤才可以」
- 「召唤员工要有一个翻卡动画，炫酷一点，类似游戏一样的召唤效果，图像或者翻卡形象用我们预设的那些头像」
- 「预设的员工要有我们已经预设好的头像」
- 「我们预设的员工就是等待招聘的员工，每个员工用户召唤好之后，可以给每个员工安装技能、插件、模型」
- 「能力内的技能与插件，市场预设的需要安装才可以使用，目前的技能是默认全安装了」
- 「这个头像还是没有固定住……我要他固定」
- 方案选 A（员工列表里分「已召唤 / 待召唤」，在原有员工和安装机制上改）。

## 目标

1. **会话列表从空开始。** 新用户开通后，会话列表里没有任何会话：不再自动建包里的频道（一对一和多人的都不建），也不再自动建「我的分身」会话。
2. **在员工列表召唤。** 员工列表分两栏：「已召唤」和「待召唤」。待召唤的员工卡片上有「召唤」按钮；点了以后播翻卡动画，建好本人和这个员工的一对一会话，动画结束直接进入这个会话。已召唤的员工按钮是「进入会话」。
3. **翻卡召唤动画。** 游戏抽卡式：卡背（熊宝纹样）→ 光效聚拢、卡片轻颤 → 翻转露出员工的熊宝头像、名字、职务 → 光芒/粒子迸发 + 「召唤成功」→ 进入会话。约 2 秒，点击任意处可跳过；系统开了「减少动态效果」时直接显示结果卡，不播动画。
4. **预设员工配熊宝头像。** 包里每个预设员工（`examples/xiongbao/agents.yaml` 的 5 个和 `agents/` 目录下的 23 个）按职业从现有 50 张预设头像（`app/src/components/portraits/preset-images.ts`）里各配一张。对应表实现时给出，交用户过目。
5. **技能要安装才生效。** 包里的技能不再在开通时自动装到员工身上。技能仍出现在「能力 › 技能」里，标「未安装」；用户在员工配置页（装配页「技能」区）勾选，才算装到这个员工。插件现在就是「上架 + 给员工安装」，不变。模型在员工配置页选，不变。
6. **会话页顶部员工卡固定。** 员工一对一会话页的顶部固定一张紧凑卡片：头像、名字、职务一行、可见范围标签（如「仅自己」），消息怎么滚它都在。消息列表开头的大介绍卡保留不动（它是开场白）。

## 不做的

- 不把预设员工改成「人才市场」里的岗位模板（方案 B）。
- 不改插件的上架与安装流程，不改模型选择。
- 不改群组：多人会话照旧在「群组」里用「新建群组」建。

## 绝不能出现的

- **老用户的东西被动了。** 已有的会话、聊天记录、员工身上已装的技能和插件一律保留。老用户和某个员工已有一对一会话的，这个员工直接算「已召唤」。
- 召唤失败却显示「召唤成功」，或者重复点出两个一样的会话。召唤要幂等：已经有一对一会话就直接进去，不新建。
- 动画卡住页面：超过约 3 秒、不能跳过，或者网络慢时动画放完了会话还没建好就跳进一个空页面。

## 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（用户选定）** | 预设员工留在员工列表，分「已召唤 / 待召唤」两栏；召唤 = 建一对一会话 + 动画；停掉开通时自动建会话和自动装技能 | 改动小，复用现有员工、会话、安装（`plugin_grants`）机制；老用户不用迁移；和「在员工列表召唤」完全对上 |
| B | 预设员工改成「人才市场」岗位模板（ROLE1 的 `role_templates`），招聘时复制出用户自己的员工 | 更像「招人」，员工列表更干净；但要把老用户已有的预设员工迁成模板，改动大，也不是用户说的「在员工列表召唤」 |

## 已定的做法（含我的判断，标「判断」的请用户确认）

- **「已召唤」怎么认：** 本人和这个员工之间有一对一会话，就是已召唤。不加新表、不加新字段。
- **召唤做什么：** 建本人和这个员工的一对一会话（已有就复用），返回会话 id。前端在这个请求成功后才放「召唤成功」并跳转；请求没回来时动画停在发光蓄力那一步等，失败就给出错误提示、卡片退回待召唤。
- **熊宝小跟班（我的分身）也要召唤**（判断）：按「会话里没有」理解，分身会话也不再自动建，分身排在「待召唤」第一位。分身身上「造员工、写技能」两项技能（`bot-creator`、`skill-creator`）和招聘与组群的工具照旧默认带着（判断）：这是系统自带的助手能力，不算市场技能；去掉的话「对话里招员工」就不能用了。
- **不再自动建的会话包括包里的多人频道**（判断）：「研发流水线」「运营跟进」这类群组也不在开通时建。
- **头像存哪：** 用现有 `portraits` 表的「预设」那一列，开通时按包里新写的 `portrait:` 字段给每个预设员工写一行；已经有头像（用户自己换过的）的不覆盖。
- **顶部固定卡放哪：** 加在会话页现有的固定标题栏里（`channel/$channelId.tsx` 里 `data-slot="conversation-header"` 那一条），把它做成带头像、名字、职务、标签的紧凑卡，不另起一层，免得顶部叠两条。

- **老用户的已装技能怎么保住**（判断）：包同步以后只是不再新加技能授予；以前包写下的授予（`plugin_grants.granted_by` 为包的标记）照旧算已安装，重新部署时也不当成「包不再给」去收回。老用户看到的「已安装」不变，不区分是包装的还是自己勾的。
- **员工记录照建，只是不建会话**（判断）：开通时预设员工和分身的员工记录照常建好（否则员工列表里没东西可召唤）；`GET /api/channels` 里自动补建分身会话的逻辑去掉，分身会话改为召唤时建。
- **分身的两项技能怎么保留**（判断）：只给分身的那条授予路径（`agents.yaml` 的 `avatar: skills:`）保留，其他员工的包技能授予停掉。分身没召唤之前，「对话里招员工」自然用不了，召唤分身后就有。
- **会话被删或归档后**（判断）：删了的员工退回「待召唤」，可以再召唤（新建会话）；归档的仍算已召唤，召唤/进入会话时把它取消归档后打开，保住聊天记录。
- **「待召唤」放谁**（判断）：凡是本人看得到、还没有和本人建一对一会话的员工都在「待召唤」，不分预设还是自建；规则只有一条，好懂。对话里新招来的员工，招来后同样点一下召唤。
- **召唤出来的会话可见范围**：和现在建一对一会话一样，仅本人；顶部卡片上的标签沿用介绍卡现有的数据来源。
- **头像对应表**（判断）：50 张够 28 个员工各配一张，必要时可重复；对应表随实现的 PR 一起给用户看，不阻塞实现，用户想换哪个随时改。

## 留给实现的

- 召唤接口：复用现有的建会话接口（`POST /api/channels`）还是另加一个专门的召唤接口，按幂等和权限检查哪个干净来定。
- 动画的具体实现（CSS 3D 翻转 + 光效即可，不引入大的动画库）、卡背图案、音效不做。
- 50 张头像里每个预设员工配哪张的对应表草稿。
- 「能力 › 技能」页「未安装」的显示方式，以及从技能页直接「安装到某个员工」的入口要不要加（装配页已能装，技能页这个入口是加分项）。
- 代码落点参考：开通时的包同步 `server/src/tenant-package.ts`（自动建频道、技能授予约 191–264 行）、分身会话 `server/src/channels/avatar-conversation.ts`（`GET /api/channels` 时调用）、个人版默认技能 `server/src/plugins/personal-defaults.ts`、员工列表 `app/src/components/app-sidebar/app-sidebar.tsx` 与 `app/src/components/bots/bot-roster.tsx`、装配页技能区 `app/src/components/bot-profile/assemble.tsx`、会话介绍卡 `app/src/components/channels/conversation-intro.tsx`。
