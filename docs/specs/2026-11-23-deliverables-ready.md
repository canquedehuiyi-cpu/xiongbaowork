# 交付即可用：员工产物在对话里直接下载、侧栏预览、程序直接访问

日期：2026-11-23　状态：待用户批准

## 为什么做

用户在京东云 v0.2.14 上让员工做一份 PPT，员工最后只在对话里贴了 HTML 预览和代码，没有交出 .pptx 文件。用户原话：
「输出 PPT 只是一个案例，我要员工可以根据任务需求直接交付所有产物：文件、代码、程序、视频、图片等能力。」
「在对话里直接下载，程序能直接打开访问」「同时需要在侧边栏可直接打开预览」「不只是单聊，群聊也一样」。

目标：员工做完活，人在对话里（单聊和群聊都一样）点一下就能拿到成品——文件能下载、能在侧栏预览，程序能直接打开用；
「交付了」必须意味着「东西真的在那儿、打得开」，不能只是一段贴在对话里的代码。

## 目标

1. **下载**：员工工作区里的任何文件（不只是用写文件工具写的，也包括脚本生成的 .pptx/.docx/.xlsx/.pdf/.zip/视频/图片），
   在对话里和交付卡上都有下载按钮。单聊、群聊都有。
2. **侧栏预览**：点产物可在对话页右侧侧栏直接预览：
   图片、视频、音频、PDF 原样预览；HTML 网页（含演示稿、前端小程序）在沙箱里渲染；Office 文件（PPT/Word/Excel）转成 PDF 预览；
   代码/文本/Markdown/CSV 以文本或表格显示。预览不了的类型给「下载」。侧栏里也能「在新标签页打开」。
3. **静态网页直接访问**：员工交付的网页目录（index.html 加 js/css/图片）通过熊宝服务器原样提供，相对路径资源都能加载，
   在侧栏或新标签页打开就是能用的网页。
4. **运行中程序直接访问**：员工在自己电脑上把程序跑起来（监听某个端口的网站/接口服务），人能通过熊宝服务器的转发地址直接访问它，
   侧栏或新标签页都能开。
5. **交付必须有实物**：交付里写的工作区文件必须真实存在且非空；声称交付了网页/程序/文件却只给了文字的，证据门挡回一次。
6. **「改动之前先问」默认关**（用户 2026-11-23 选「默认关（推荐）」）：个人版首次给员工工具时不再默认开启；
   已经存在的设置不动。底线（删除、对外发送、危险命令、敏感路径）照样要人批准。
7. **验收**：一组用真实模型（DeepSeek）跑的「各类产物都要真交付」题，全部通过才算达成。

## 不做（非目标）

- 不做公开分享链接：所有下载、预览、访问都要登录，且只有能看这段对话的人能看（群聊即群成员）。
- 不做把产物推到外部（网盘、邮件、对象存储）的自动同步。
- 不做在线编辑产物（只预览）。
- 不改员工电脑的隔离方式（单容器部署仍是「一台共享电脑」）。
- 设备运行时（产物在配对的个人电脑上）：首期只做「下载」与「预览」中能走现有设备通道的部分；运行中程序转发首期只做云端电脑（cloud），
  设备上的程序转发列为后续（见「留给后续」）。

## 反目标（做到了也算失败）

- 任何产物能被对话之外的人访问（包括同部署其他用户、未登录者）。
- 员工的网页/程序在熊宝应用的同源下执行脚本（能读到人的登录态）。
- 转发能被用来访问员工电脑上的系统服务、或从员工电脑去打内网/其他员工的电脑。
- 交付卡显示「可下载」，点了却 404。

## 现状（摸底结论，2026-11-23）

- 对话里只有 `computer_write_file` 写出的文件有下载链接（`app/src/components/channels/turn-artifacts.tsx`、`app/src/lib/computers/artifact.ts`）；
  脚本生成的文件没有。交付卡（`app/src/skins/xiongbao/delivery-chat.tsx` 的 `EvidenceItem`、任务页 `tasks.$taskId.tsx`）只念路径，代码注释「下载入口另票再接」。
- 下载路由 `GET /api/computers/:botId/files/download?path=` 已有：归属检查、走 `computer_download_file` 治理与审计、电脑端 100MB 上限；
  响应强制 `application/octet-stream` + `attachment`（`shared/file-download.ts`，有意为之，防止 HTML/SVG 在应用源上执行）。**没有 inline**。
- 生成的图片/视频在 `/api/media/:id`，已经是 inline + `nosniff` + `sandbox` + Range，只能生成者本人读。
- 对话页右侧有 `DetailPanel`（设置 / 电脑实时画面两种内容，URL 参数切换），熊宝皮肤另有对话侧栏（环境/目标/上下文/输出内容），单聊和群聊都挂。**没有预览面板，没有 iframe。**
- 服务器经 `server/src/computer/client.ts`（带 computer token）调 agent-computer 的 HTTP 接口；**没有任何把请求转到员工电脑内某端口的通道**。
- 证据门（`server/src/tasks/evidence-gate.ts`）对 `workspace_file` 只查路径形状，不查存在；`note` 加一条 checks 就能交付。
- 「改动之前先问」默认开在 `server/src/plugins/personal-defaults.ts` 约 875 行（`enabled: true`，`onConflictDoNothing`），三个集成测试钉住。
- 镜像已有文档工具链：python-pptx、python-docx、openpyxl、LibreOffice（单镜像）等。

## 方案比较（用户已选）

- 程序访问：A 只做静态网页；B 只做运行中程序转发；C 两种都做。**用户选「两种一起做」**（2026-11-23）。
- 内容源：独立端口（不用域名，京东云多放行一个端口）／泛子域名（隔离最好，要域名和证书）／两种都支持。**用户选「两种都支持」**。
- 「改动之前先问」：默认关（只影响新授权）／默认关并把已有的也关／保持现状。**用户选「默认关（推荐）」**。
- 交付方式：**用户定「在对话里直接下载，程序能直接打开访问」，并要求「侧边栏可直接打开预览」「群聊也一样」**。

## 做法（已定的部分）

### A. 产物登记与下载（单聊、群聊、交付卡统一）
- 一轮里员工电脑上**新出现或被改动**的工作区文件，都算这一轮的产物，在对话里列出来带下载按钮——不只认 `computer_write_file`：
  每位员工的工作区本来就是各自的目录；一轮开始时电脑端记一份快照（路径、大小、修改时间），一轮结束（以及交付时）再比一次，
  新增/改动的文件清单作为这一轮的产物事件存库（最多扫 20,000 个文件、只记前 200 个产物，超了在事件里注明截断），群聊里按发言员工各自的工作区算，
  对话（单聊、群聊）按这个事件画「本轮产物」。忽略 `tool-outputs/`、隐藏目录、`node_modules` 等（清单写进代码，可测）。
- 交付卡上的 `workspace_file` 行带下载按钮和「预览」按钮。交付事件补上员工 id（群聊交付卡里目前缺），任务页同样能拿到负责员工。
- 下载继续走现有下载路由（归属/群成员检查 + 治理审计），不放宽 `attachment` 的安全决定。
- 群聊：能看这段群聊的人就能下载/预览其中员工交付的产物（权限按群成员判定，补集成测试）；单聊只有对话本人。

### B. 侧栏预览
- 对话页右侧 `DetailPanel` 加第三种内容「预览」（URL 参数 `preview=<产物标识>`），单聊、群聊同一套；熊宝皮肤的对话侧栏「输出内容」块里的产物点了也打开它。
- 预览用**独立的、无凭据的内容源**提供（见 C），在 iframe 里用 `sandbox` 加载；应用源上永远不直接渲染员工产物。
- Office 文件：服务器请员工电脑用 LibreOffice 转成 PDF 再预览（结果缓存在员工工作区的隐藏目录，按源文件修改时间失效）；没有 LibreOffice 的环境显示「下载」。
- 文本/代码/Markdown/CSV：读取前 1MB，在应用里以纯文本/表格显示（不执行）。

### C. 静态网页与运行中程序的访问（同一个「内容源」）
- 员工的网页和程序**永远不在应用的源上**打开。两种内容源都支持（用户 2026-11-23 选「两种都支持」）：
  - **独立端口（默认）**：同一服务进程再监听一个端口（例如 3773，`XIONGBAO_CONTENT_PORT`，单容器多映射一个端口；部署手册写清京东云安全组放行）。端口不同即不同源。
  - **泛子域名（配了就用）**：`XIONGBAO_CONTENT_DOMAIN=apps.example.com` 时，每个打开的目标一个子域（`<令牌短码>.apps.example.com`），需泛 DNS 与证书。
  两种都没配（或端口不可达）时，不提供「打开程序」，只提供下载与静态预览（HTML 在 `CSP: sandbox` 的 iframe 里，降级说明写进界面）。
- 令牌：人登录后点「打开」时，服务器发一个短期（30 分钟，打开状态下自动续）、绑定「这个人 + 这个员工 + 这个目录或端口」的签名令牌。
  首次访问 `/__open/<令牌>` 时在内容源上换成一个 HttpOnly cookie（只在内容源上），然后跳转到目标根路径，地址栏不再带令牌；
  令牌/cookie 过期后需在对话里重新点「打开」，已打开的 WebSocket 到期断开。
- **根路径问题**：程序常按 `/` 写资源和接口（`/api/todos`、`/static/x.js`）。子域名模式下每个目标独占一个源，天然没问题；
  独立端口模式下，内容源按 cookie 确定「这个浏览器当前打开的是哪个目标」，根路径请求直接转给它——同一浏览器在独立端口模式下同时只能开一个程序，
  再打开另一个会替换前一个（界面提示）。不要求员工改写程序路径。
- **静态网页**：令牌指向员工工作区里的一个目录，`/u/<令牌>/<相对路径>` 原样返回文件（正确的 Content-Type，`nosniff`），目录默认 `index.html`；不能跳出该目录。
- **运行中程序**：令牌指向员工电脑上的一个端口（只允许 1024–65535，且只允许员工自己起的进程监听的端口，不允许 agent-computer 自身和系统端口）。
  「员工自己起的」按系统用户判定：每位员工本来就有独立的系统用户（「每员工独立系统用户」已上线），电脑端读监听表（如 `/proc/net/tcp*` 的 uid）确认该端口的监听进程属于这位员工的系统用户，否则拒绝（共享电脑里也就无法转到别的员工的程序）；
  服务器把 `/u/<令牌>/…` 的 HTTP 请求（含 WebSocket，便于热更新类开发服务器）转给员工电脑的 agent-computer，再由它转到容器内 `127.0.0.1:<port>`。
  agent-computer 新增一个带 computer token 的转发接口；服务器侧复用 `client.ts` 的鉴权与出口策略。只转 HTTP/WS，不做任意 TCP。
- 员工怎么告诉人「程序在哪」：新增一种交付项 `app`（`{ kind: "app", port, path?, title }`）和对应的「打开」按钮；员工也可以在对话里用工具
  （例如 `publish_preview`）返回一个可点的预览卡片。交付时证据门会实际请求一次该端口/目录首页，打不开就挡回。
- 程序转发和内容源要做**安全审查**（见「安全」），审查通过才合入。

### D. 证据门要求实物
- `workspace_file`：证据门经 gateway 查文件存在且大小 > 0（一次 stat），不存在就挡回并说明哪一项。
- `app`：请求一次首页，2xx/3xx 才算。
- 交付里只有 `note`、而这件活的验收标准或员工自己的标题里提到「文件/网页/程序/PPT/文档/表格/视频/图片」等实物词时，挡回一次，提示「把产物存成文件交付」。
  逃生口：员工在交付里明确写明「这件活没有文件产物」（note 里的固定说法，写进交付规约）就放行。每轮最多挡一次（状态记在这一轮的对话历史标记里，同第十八轮核对门的做法），避免卡死。
- 设备运行时（产物在配对的个人电脑上）：首期不做存在性检查（照旧只查路径形状），在交付卡上标「未核实」。

### E. 「改动之前先问」默认关
- `personal-defaults.ts` 首次授予工具时不再写 `enabled: true`（改为不写或写 false，取对现有代码影响最小者）。已有行不动、不做迁移。
- 同步三个集成测试的期望（逐条列在 PR 里）。CHANGELOG 写清楚：新员工默认不再逐条询问写文件/跑命令，底线照问；要逐条问的人在「设置 → 审批」里打开。

### F. 员工侧提示
- 交付规约（系统提示里交付那一段，及 `deliver_task` 说明）加一句：「交付的是文件/网页/程序就把它存在工作区里并作为 workspace_file / app 交付；不要只把内容贴在对话里。」
  控制在提示预算内。

## 安全（审查要点）

- 内容源与应用隔离：独立子域名优先；同域时必须 `CSP: sandbox`（不含 allow-same-origin）、`X-Content-Type-Options: nosniff`、不带应用 cookie。
- 令牌：签名（服务器密钥）、短期、绑定人/员工/目标、不可枚举；群聊里按群成员资格签发；撤出群/员工被删即失效。
- 转发：只到员工自己的电脑、只到 127.0.0.1 上的非保留端口；不跟随员工程序返回的重定向到别的主机；请求体/响应体大小与时长上限；按员工限流；审计每次「打开」。
- 静态目录：规范化路径，禁止 `..`、符号链接逃逸。
- 下载：沿用现有 `attachment` 与治理审计，不放宽。

## 验收（真实模型，DeepSeek，单聊与群聊各跑）

新增评测题组「交付即可用」，每题判分检查：
1. PPT：交付 .pptx，能下载、python-pptx 能打开、页数 ≥ 要求；侧栏预览（转 PDF）可见。
2. Word 报告：.docx，能打开、含指定标题。
3. Excel：.xlsx，含指定表头和公式结果正确。
4. 静态网页小程序（如计算器/小游戏）：交付目录，经内容源打开首页 200，页面在无头浏览器里能完成一个交互。
5. 带后台的小程序（如 Python/Node 的待办接口 + 页面）：交付 `app`，经转发访问首页 200，接口能增删一条记录。
6. 图片：交付一张图（生成或脚本绘制），能下载、侧栏预览。
7. 视频：交付一段几秒的视频（ffmpeg 合成或生成服务），能下载、侧栏可播。
每题单聊、群聊各一次（共 14 次）；每次失败允许重跑一次，14 项全部通过（含重跑）才算达成，结果（含重跑次数）写进验收文档。
题 4、5 用 CI 里已有的 Playwright/Chromium 做浏览器交互检查。

## 分期（每期独立 PR，CI 全绿合入；界面改动推送前截图给用户确认）

1. 审批默认关 + 证据门查实物 + 员工侧提示（服务器）。
2. 产物登记与下载：一轮产物清单、对话（单聊/群聊）「本轮产物」与交付卡的下载按钮（服务器 + 界面）。
3. 侧栏预览：图片/视频/PDF/文本、HTML 沙箱、Office 转 PDF（界面 + 服务器 + 电脑端）。
4. 内容源与静态网页访问（服务器，含安全审查）。
5. 运行中程序转发（电脑端 + 服务器 + 界面，含安全审查）。
6. 验收题组与真实模型评测、验收文档。

## 留给实现者自定的

- 一轮产物对比的具体实现（电脑端列目录还是记录写入事件），只要满足「脚本生成的文件也能列出」且有测试。
- 令牌格式与签名方式、缓存目录名、预览面板的具体样式（照现有 `DetailPanel` 风格）。

## 留给后续（本项目不做）

- 设备运行时（配对个人电脑）上的运行中程序转发、以及「选了项目」时项目根下文件的下载（现有注释已说明根目录不明，需单独安全审查）。
- 公开分享链接、产物版本历史。
