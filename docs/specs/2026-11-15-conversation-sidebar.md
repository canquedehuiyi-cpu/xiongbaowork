## 为什么做

用户在一个对话里常常看不清：员工在哪干活、正在做哪件事、做到哪一步、用了多少、产出在哪。Claude Code 桌面端的侧栏把这些一眼摆清楚，用户要熊宝的员工单聊和群组对话「同样的侧边栏，能让用户更清楚的了解清晰明白看到」。

## 用户说过的

- 「我需要我们的员工或者群组对话需要支持这样的侧边栏，能让用户更清楚的了解清晰明白看到」（附 Claude Code 桌面端侧栏截图：环境、目标、上下文、输出内容）
- 「跟 Claude Code 桌面端的同样的侧边栏」
- 「选 A，出设计稿」（上下文：总量准确、分类估算、新做压缩）
- 「侧边栏是可折叠展开的」
- 「侧栏设计稿可以，写成正式设计文档」
- 长期规矩：改完先给截图，没问题再推。

## 目标

1. **右侧常驻侧栏**，员工单聊和群组对话都有，四块与 Claude Code 桌面端一致：环境、目标、上下文、输出内容。
2. **可折叠**：每块单独收起或展开（收起时标题右侧留一句摘要）；整栏可收成 56px 图标条（目标有待确认时带橙点，上下文显示百分比小条，输出内容显示数量）。收起状态按对话记住。
3. **环境**：员工在哪干活（云端，或某台电脑及是否在线）、项目或工作文件夹、模型；群组里换成成员列表（头像、状态点、在哪、此刻在做什么）。
4. **目标**：这个对话正在做的事（最近一张任务卡的标题）、「第 N 轮 · 上次检查：…」一行；有待确认时给「去确认」按钮。
5. **上下文**（方案 A）：「已使用 X%　已用 / 上限」彩色条；分类列出用量和占比（消息、人设与系统提示、工具、技能、记忆、自动压缩预留、空余）；「距自动压缩还剩 …」和「压缩会话」按钮。群组里每位员工一根小条，点名字看明细。外部员工写「由 Codex 自己管理」。
6. **压缩会话**：手动点或接近上限自动触发；把较早的消息总结成一段，原消息仍留在对话里可翻看；对话里出现「已压缩 · 看摘要」分隔线。
7. **输出内容**：这个对话产出的文件、表格、链接、代码改动，一行一个，标类型；超过 3 条显示「查看全部 N 项」。
8. **手机**：对话顶栏一个按钮打开全屏侧栏，四块同样排列，顶部「返回对话」。

## 不做

- 不按类别精确计 token：只有总量是服务商报的真实数，分类是估算。
- 不显示金额。
- 外部员工不做压缩（它的上下文由它自己管）。
- 不在侧栏里编辑员工配置（齿轮跳到现有配置页）。
- 外部员工的改动清单和计划步数（`acp.diff`、「x / y 步」）等外部员工第三期界面上线时再接；这一期外部员工的侧栏只有环境、目标（任务卡）、「由 Codex 自己管理」和附件类输出（我的决定）。

## 反目标

- 把估算的分类数字说成精确值（界面上分类数旁不写「精确」，总量取不到时显示「—」，不编数）。
- 压缩后员工忘了关键约定或用户的决定，用户却看不出来（必须能「看摘要」）。
- 侧栏让对话区变得拥挤到看不清：桌面宽度不足 1200px 时侧栏默认收起成图标条。

## 约束

- 多租户：侧栏数据只给能看到这个对话的人，接口按现有对话权限过滤；所有查询带租户帧。
- 用量只来自 `model_token_calls`（服务商报数，`usage_status = 'unknown'` 的不算），不自行估总量。
- 文案中文，沿用工作台 `--wb-*` 令牌，只作用于默认皮肤。

## 做法（用户已选 A）

- A（选定）：总量准确（最近一次模型调用的真实输入 token）；上限来自模型库新增的「上下文长度」；分类按组装 prompt 时各部分字数比例分摊；新做压缩，手动加自动。
- B：同 A 但不做压缩。未选：用户要和 Claude Code 一样的完整体验。
- C：只显示总量和剩余。未选：离要的样子太远。

## 设计

### 1. 数据从哪里来

**环境**
- 运行位置：内置员工按部署运行方式（`config.tenantRuntime`：云端 / 设备）；设备模式和外部员工显示电脑名与在线状态（现有设备记录）。
- 项目：`project_context_bindings`（按员工 + 电脑），没有则不显示这一行；「+」打开现有项目选择器。外部员工显示工作文件夹名（`workdirRef` 对应的共享文件夹名）。
- 模型：员工绑定的模型（`agent_profiles.model_ref` / `platform_model_ref` → 模型库的显示名）；外部员工写「外部员工 · Codex · 用你自己的订阅」。

**目标**
- 卡片：`tasks` 里 `channel_ref = 本对话线程` 的最新一张（新增索引 `(tenant_id, channel_ref, updated_at)`）；群组按群组的频道 id 取。
- 第 N 轮：`thread_runs` 里本线程的运行次数。
- 上次检查：最新一张卡的状态一句话（进行中 / 等你确认 / 已完成 / 失败）加员工最近一条回复的第一句（截 60 字）；外部员工有计划时用「x / y 步」。
- 待确认：本线程有挂起的审批时显示「去确认」，跳到对话里那张许可卡。

**上下文**
- 已用：本线程、本员工最近一次 `outcome = completed` 且 `usage_status` 为 reported 或 partial 的调用的 `input_tokens`（新增索引 `(tenant_id, thread_id, agent_id, started_at)`）。没有数时整块显示「还没有用量数据」。
- 上限：模型库 `model_registry` 和 `platform_model_pool` 新增 `context_window integer` 列。新增模型时，从模型目录（models.dev 的 `limit.context`，`model-catalogue.ts` 解析时保留下来）预填，管理员可改。取值顺序（我的决定）：员工绑定的模型库行 → 平台模型池行 → 按实际调用的服务商和模型名到模型目录里查（覆盖用部署默认模型的员工）→ 都没有时只显示已用数，不显示百分比、不自动压缩。
- 已用的口径（我的决定）：已用 = 计量记录的 input_tokens。AI SDK v3 报的输入总数已含缓存读写（如 Anthropic），不再另加缓存数。
- 分类：组装 prompt 时（`builtInAgentConfiguration` 与之后的消息拼接处）按段统计字数：人设与系统提示（身份、人设、手册、指令等段）、工具（工具说明与 schema）、技能、记忆（个人记忆中间件注入的部分）、消息（对话历史，含压缩摘要）。每次运行把比例写进新表 `thread_context_breakdowns`（tenant_id、thread_id、agent_id、run_id、shares jsonb、created_at），侧栏用最近一行的比例乘已用总量得到各类数。
- 自动压缩预留：上限的 10%。空余 = 上限 − 已用 − 预留，不小于 0。
- 「距自动压缩还剩」= 空余。

**输出内容**
- 任务卡匹配：`tasks.channel_ref` 有的写线程 id、有的写频道 id，单聊两个都匹配。
- 本线程各任务卡的 `deliverable_ref`（组件和附件），加上外部员工的改动汇总（`acp.diff`），按时间倒序、去重。类型：文件（附件）、表格、链接、改动、报告。

### 2. 接口

- `GET /api/threads/:threadId/sidebar?agentId=` → `{environment, goal, context, outputs}`，一次返回四块。群组：`environment.members[]`，`context.perAgent[]`（每位员工 `{agentId, used, limit, percent}`），`?agentId=` 取某位员工的分类明细。前端在运行结束、审批变化时刷新，平时 15 秒一次。
- `POST /api/threads/:threadId/compact {agentId}` → 发起手动压缩，只有能在这个对话里说话的人可调；返回压缩前后预计用量。外部员工返回 409。

### 3. 压缩

- 范围：一个员工在一个线程里的历史。保留最近 10 条消息不动，把更早的消息（含上一次的摘要）总结成一段。
- 做法：用该员工自己的模型，用固定的总结指令（保留：用户的决定和约定、未完成的事、关键事实与数字、文件和链接名；去掉：寒暄、重复、已被推翻的内容），结果存新表 `thread_compactions`（tenant_id、thread_id、agent_id、upto_message_id、summary、tokens_before、tokens_after、auto boolean、created_at）。
- 生效：组装 prompt 时，`upto_message_id` 及之前的消息换成一条「早前对话摘要」系统消息；原消息仍在线程里，对话界面照常显示。
- 自动：一轮开始前，若上一轮已用 ≥ 上限 − 预留，先压缩再跑；压缩失败不挡这一轮，界面提示一次。
- 界面：分隔线「已压缩：较早的 N 条消息已总结 · 看摘要」（自动的写「已自动压缩」），「看摘要」展开摘要全文。
- 压缩本身的模型调用照常计量，算在本线程。

### 4. 界面

- 单聊：`channel/$channelId.tsx` 现有 `DetailPanel` 里放侧栏，替换原有 `AgentProfile` 区块；`ConversationApprovals` 并入「目标」的待确认提示。
- 群组：`group/$channelId.tsx` 新增同样的右侧面板。

**群组的口径（我的决定）**：群组里每个人和每位员工各有一条自己的线程（`group_bot_threads`），大家看的是共享的群消息。所以群组侧栏按群组频道取数：环境的成员列表对全群一样；目标（群频道的任务卡）和输出内容按查看者取——任务卡和附件按人隔离，每人看到自己名下的那部分（全群共享要另做共享设计，这一期不做）；上下文按「当前查看的人 × 每位员工」取各自那条线程的用量。「压缩会话」只压缩当前查看者和这位员工之间的那条线程；共享群消息里不插分隔线，改为在侧栏该员工的上下文行下方显示「已压缩 · 看摘要」。
- 宽度 300px；桌面宽度不足 1200px 时默认收成图标条；手机为全屏页（工作台手机布局里的详情页样式，顶部「返回对话」）。
- 折叠状态存浏览器本地（键：线程 id），读不到就默认全部展开。
- 只作用于默认皮肤。

## 测试与验收

- 服务器：sidebar 接口四块的取数（含没有用量、没有上限、外部员工、群组），权限（别人的对话 404），分类比例落库，压缩（手动、自动阈值、失败不挡运行、摘要替换进 prompt、原消息仍在），外部员工 409。
- 前端：四块渲染、每块折叠与摘要、整栏图标条、宽度不足自动收起、手机全屏、压缩确认弹窗与分隔线、「看摘要」。
