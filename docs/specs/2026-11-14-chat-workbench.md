# 熊宝聊天工作台：微信 / 钉钉 / 飞书式界面重排

日期：2026-11-14 · 状态：待用户确认
设计稿（可点击）：https://claude.ai/artifact/2DL9zxBwSH4YSKx3C8tB7g （v2，用户确认「方向可以，按这个写详细设计」）；同一份源文件存在仓库 `docs/specs/assets/2026-11-14-chat-workbench-mock.html`，颜色、圆角、阴影的具体数值以其中 `:root` 变量为准。
前置：依赖召唤员工分支（PR #596 设计稿对应的 `feat/summon`）先合入——工号函数 `employeeNumber`、人才市场、`summonKind/summoned` 都来自那里。

## 为什么做

熊宝是给「一人公司」用的：一个人带一队 AI 员工干活。现在的界面是「后台工具」的样子——左边一长串导航（工作管理、员工资源、更多……），设置、管理入口到处都是，新用户不知道从哪开始。用户要的是像微信、钉钉、飞书那样的工作台：**聊天是主场，员工像真同事，设置收起来**，整体要「更高端、大厂风格、拟人化」。

## 用户说过的

- 「我们在研究个方案，把项目变成一个类似聊天软件，如微信、钉钉、飞书的工作台，把一些设置隐藏」
- 「先出设计图或者截图，我确认再推进」
- 「方案方向对，再优化，更高端，大厂风格，拟人化」
- 「方向可以，按这个写详细设计」
- 「接下来修改完的东西都要先给我截图，没问题再推」
- 界面要沿用现有的暗色风格（「不能是这个白色的 UI，得走之前的」）

## 目标

1. **四个入口的图标栏。** 最左一列图标导航：消息、通讯录、工作台、我。取代现在左栏的长导航和「会话 / 员工 / 群组」切换。
2. **消息。** 会话和群聊合成一个列表（群聊显示成员拼图头像），筛选标签「全部 / 未读 / 待我确认 / 群聊」，右上「＋」收纳「新对话 / 新建群组」。点开就是对话。
3. **通讯录。** 顶部入口「人才市场」（带待召唤人数）和「我的群组」；下面按部门列出本人的员工（组织架构），每位员工一张卡：头像 + 状态点 + 职务 + 此刻在做什么。末尾「招一位新同事 → 人才市场」。
4. **工作台。** 问候语 + 今日数据（在岗员工、今日完成、等你确认、今晚定时任务）+ 今日动态（谁完成了什么）+ 应用格子：任务看板、自主工作、Waker、人才市场、能力、连接；「管理」区（模型与套餐、审计、平台设置）只有管理员看得到。
5. **我。** 个人卡（名字、套餐徽标、员工数、加入天数）+ 个人资料、我的电脑、通知、套餐与用量、外观、设置（全部高级设置）、帮助、退出。
6. **拟人化员工。**
   - 状态点：空闲（绿）/ 忙碌（橙）/ 休息（灰），所有出现员工头像的地方一致。
   - 「此刻在做什么」：列表、通讯录卡片、对话顶栏都显示。
   - 员工名片（右侧抽屉）：封面、工号、部门、入职第几天、此刻、性格、模型、擅长的技能；按钮「发消息 / 配置 / 交给他一个任务 / 拉进群」。
   - 对话里：「正在输入」、任务进度卡、需要你拍板时的按钮卡，统一成设计稿里的样式。
7. **高端质感。** 设计稿的视觉规范落到主题变量：统一圆角、细描边、柔和阴影；主色熊宝红到暖橙渐变，只用于自己的气泡、选中态、主按钮；深浅主题都做，默认沿用用户已选的主题。
8. **手机。** 宽度不足 768px 时只显示图标栏（改成底部标签栏）和列表，进入对话全屏，返回回到列表，和微信一致。

## 不做的

- 不改后端业务逻辑；除下面「新增的数据」外不加接口。
- 不做日报、打卡（设计稿里「整理今日日报」按钮先不做，留作后续）。
- 不删任何现有页面：旧路由全部保留可直达，只是换了入口位置。
- 不改皮肤系统本身：opendots / openduet / openmuse 三个皮肤照旧可选；新工作台是默认外观。

## 绝不能出现的

- 某个现有功能从界面上彻底找不到了（每个旧导航项都要有新位置，见下表）。
- 管理员才能看的入口对普通用户显示。
- 状态点或「此刻在做什么」显示假数据：拿不到就不显示，不编。
- 白色界面突然替换掉用户的暗色主题。

## 旧入口 → 新位置

| 现在 | 新位置 |
|---|---|
| 会话 / 群组切换、会话列表、群组列表 | 消息（合并列表） |
| 员工切换（侧栏员工列表） | 通讯录 › 组织架构 |
| 新对话、新建群组 | 消息列表右上「＋」 |
| 人才市场（/bots） | 通讯录顶部入口；工作台应用格子 |
| 任务看板、自主工作、@Waker | 工作台应用格子（常用） |
| 能力、连接 | 工作台应用格子 |
| 教员工做事（浏览器）、组团流程、团队 Bot、审批 | 工作台应用格子（更多） |
| 账户菜单：我的分身、套餐与用量、设置 | 我 |
| 管理（仅管理员） | 工作台 › 管理区（仅管理员） |
| 设置里的各分页 | 我 › 设置（原设置页照旧） |

## 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A：做成默认外观的新外壳（推荐）** | 给默认皮肤 `xiongbao` 加一个 `Frame`（皮肤系统已有的整套外壳替换点），实现图标栏 + 列表栏 + 主区 + 名片抽屉；列表栏按当前入口渲染消息 / 通讯录 / 工作台 / 我 | 沿用 opendots（已有左侧图标栏）、openduet（已有底部标签栏）的先例；不碰路由，旧页面在主区照常渲染；其他皮肤不受影响；出问题可以一键切回原外观 |
| B：直接改写 AppShell 与侧栏 | 改 `app-shell.tsx` / `app-sidebar.tsx` | 影响所有皮肤，回退难 |
| C：新开一套页面 | 新路由树 | 重复实现大量页面，工作量最大 |

推荐 A。

## 已定的做法

- **入口状态**：当前入口由路由决定（`lib/navigation.ts` 的 `NAVIGATION` 加一个 `rail: "msg" | "contacts" | "work" | "me"` 归属字段），刷新、直达链接都能落到正确入口；所有皮肤和侧栏仍用这一份导航表。
- **列表栏**：
  - 消息：复用现有会话列表数据（`channelListQueryOptions`、`ChannelSummary.lastMessageAt/lastReadAt`、未读判断），群聊来自群组列表；「待我确认」筛选用现有 needs-you 数据。
  - 通讯录：复用侧栏员工数据（`listedEmployees` / `employeeGroups`）。
  - 工作台、我：列表栏显示常用项；主区是工作台首页 / 个人页。
- **主区**：路由页面照常渲染；工作台首页、个人页是两个新页面（`/workbench`、`/me`），其余都是现有页面。
- **状态点**：由现有 `useProfileStatus(agentId)` 映射——`working`→忙碌、`resting`→空闲、`paused`→休息、`unknown`/null→不显示。列表里大量员工时用一次批量查询（新增一个按多个员工取运行中任务的读取，见下）。
- **「此刻在做什么」**：取该员工运行中任务的 `title`（`AgentRunningTask`）；没有运行中任务时，显示最近完成的一件（`lib/autonomous/unified.ts` 的 `lastRunAt/lastStatus`）或不显示。
- **员工名片**：工号用召唤动画里的 `employeeNumber(agentId)`；入职天数用员工资料的创建时间；性格取人设的「怎么说话」第一句；擅长取该员工已装技能名；模型取员工模型设置。
- **部门**（新增数据）：员工资料加可选字段 `department`（文本）。预设员工在包里写好（研发部、产品部、设计部、行政部……），召唤时随复制带过去；用户可在员工配置里改；没有部门的员工归「未分组」。
- **工作台今日数据**：在岗员工 = 本人员工数；今日完成 / 等你确认 / 今晚定时任务 = 现有任务、needs-you、自主工作数据的当天计数；今日动态 = 当天完成的任务按时间倒序。
- **管理区**：沿用 `role === "admin"` 与 `navigationFor(role, edition)` 的现有判断；个人版不显示管理区。
- **主题**：设计稿的颜色、圆角、阴影写成默认皮肤的主题变量（`theme.css` / 皮肤 css），深浅各一套；`xiongbao-theme` 的用户选择照旧生效。
- **手机**：小于 768px 图标栏变底部标签栏，列表全屏，进入对话后隐藏标签栏、顶部有返回。

## 新增的数据（仅此两项）

1. `agent_profiles.department`（可选文本）及包字段 `department:`；召唤复制时带上。
2. 一个批量读取：给多个员工取「运行中任务的标题」，供状态点和「此刻在做什么」用，避免每个员工各发一次轮询。

## 分阶段交付（每阶段先截图给用户确认再推）

1. 外壳与四个入口：图标栏、消息列表、我页面、旧入口全部有新位置；管理区权限。
2. 通讯录与名片：组织架构、员工卡、名片抽屉、部门字段。
3. 拟人化：状态点、此刻在做什么（含批量读取）、对话顶栏、进度卡与拍板卡样式统一。
4. 工作台首页：问候、今日数据、今日动态、应用格子。
5. 手机布局与整体视觉打磨。

## 实现前已澄清的问题（我的判断，用户可改）

- **默认外观怎么换**：`xiongbao` 皮肤现在没有 `Frame`，用的是 `AppShell` + 现有侧栏。新工作台作为 `xiongbao` 的 `Frame` 接管默认外观；把现在的外观保留成一个新皮肤「经典」（无 `Frame`，等于现状），设置 › 外观里可切回——这就是「一键切回原外观」。
- **视觉依据**：以仓库里的设计稿源文件为准（见开头），其 `:root` / 深浅两套变量直接映射到默认皮肤的主题变量。
- **工号**：用召唤分支的 `employeeNumber(agentId)`（FNV-1a 哈希取 4 位，`XB-` 前缀）。
- **「待我确认」**：现有数据按员工给出（`useWaitingByBot` / `waitingOnYou`）。筛选规则：该员工有待确认事项时，他的一对一会话算「待我确认」；群聊不参与这个筛选。拍板卡沿用对话里现有的确认 / 审批卡，只统一样式。
- **今日 / 今晚的口径**：按用户浏览器本地时区。「今日完成」= 今天 0 点以来状态变为完成的任务（用任务的更新时间与状态判断；实现时若任务表没有可用的完成时间，改用「今天更新且状态为完成」，不新增字段）；「今晚定时任务」= 现在到次日 06:00 之间计划运行的自主工作项（`nextRunAt`）。
- **状态映射**：实际枚举是 `working | resting | paused | unknown`。`working`→忙碌（橙）、`resting`→空闲（绿）、`paused`→「已暂停」（灰，用户主动暂停，不叫「休息」）、`unknown`/空→不显示状态点。
- **部门**：员工主人可在员工配置里改。预设员工的部门写在包里（研发部、产品部、设计部、测试部、运营部、行政部、总经办，按职务分配）；已召唤的副本没有部门时，读的时候回退到它来源预设的部门（`summoned_from`），不需要数据迁移；自建员工没有部门归「未分组」。
- **路由归属**：`/bots`（人才市场）和员工资料 `/bots/:id/*`（包括我的分身）归「通讯录」；会话、群聊归「消息」；任务看板、自主工作、Waker、能力、连接、教员工做事、组团流程、团队 Bot、审批、管理归「工作台」；设置、套餐归「我」。

## 留给实现的

- 图标、具体间距与动效细节（以设计稿为准，可微调）。
- 列表栏宽度是否可拖动（沿用现有可拖动）。
- 名片抽屉在窄屏上的形态（全屏页或底部弹层）。
