# 熊宝员工四项能力深度优化：设计稿（待确认）

日期：2026-11-20　状态：**已通过**（用户 2026-11-20「方案通过」，技能生效方式选 C；同意网页抓取内联上限降到 8KB、个人版默认打开记忆）

## 为什么做

用户希望把员工自身的生产能力（社区能力除外）补到 Codex、Hermes Agent、OpenClaw、Grok Bot、Muse Code 的水平，最好能超过。要补的有四项：

1. 常规办公和编码
2. 常驻和主动
3. 记忆和自我改进
4. token 消耗

现状：在 DeepSeek 上和 Codex 实测，五道题 5/5 打平。输入 token 看板路径是 Codex 的 1.6 倍，单聊路径是 2.0 倍；耗时约 1.5 倍。员工不会从经验里自己学东西。个人版没有记忆。

## 总体做法

四个子项目各自独立，各有各的验收数字，按下面的顺序一个个做，每个子项目单独出 PR、过 CI、合入：

0. **先扩评测**，作为后面所有改进的尺子：加难题和电脑操作题，并接入逐步计量。
1. **token 消耗**：最便宜、见效快，做完以后每个子项目都跟着省钱。
2. **记忆和自我改进**：和竞品差距最大的一项。
3. **常驻和主动**。
4. **常规办公和编码**：依据第 0 步的难题结果，针对性地补。

---

## 子项目 0：评测扩充（尺子）

- 在现有五道题之外，再加三类题：
  - 「真需要计划和子代理」的难题，例如 `compare`：对比 5 个开源项目；
  - 跨多文件重构；
  - 终端类任务：装依赖、修构建、跑测试。
- 电脑操作题：网页表单填写、多页面信息汇总。
- 每次评测都跑三方：熊宝、Codex，以及换成更强模型的熊宝，用来分清差距有多少来自模型、多少来自做法。
- **验收**：报告能同时列出难题通过率、逐步 token 和墙钟时间。

## 子项目 1：token 消耗

**目标**：在通过率不下降的前提下，五道题合计输入 token 降到 Codex 的 1.2 倍以内（现在看板 1.6 倍、单聊 2.0 倍）。

| 杠杆 | 现在 | 改成 |
|---|---|---|
| 网页抓取 | 默认返回 2 万字，超过 16KB 只给头尾 | 全文存进工作区，正文内联最多 8KB，回传摘要加文件路径，模型按需用读文件、检索工具取片段（和 Codex 用 curl 落盘一样） |
| 记忆注入 | 每轮整包注入，最多约 2.4 万字符 | 按和这条消息的相关程度取前 K 条，设字符预算（例如 4 千字），其余靠 recall 工具按需取 |
| 技能挑选 | 每轮多一次模型调用 | 同一段对话里缓存上次的挑选结果，消息主题变了才重挑；或者改成本地相似度匹配，不调模型 |
| 轮次之间压缩 | 自动压缩默认关 | 默认打开，超过阈值时自动压缩较早的轮次 |
| 提示词体积 | 没有基线 | 评测记录每段提示词的体积和缓存命中率，设上限守卫 |
| 轻量轮 | 和工作轮用同一个模型 | 巡检、跟进这类轻量轮可配一个便宜模型 |

网页抓取上限的改动会碰到已有断言（`web-tools.test.ts` 的 5_461）：用户已于 2026-11-20 批准。

## 子项目 2：记忆和自我改进

**目标**：员工越用越懂你、越用越会干。同一类任务第二次做时，步数和 token 明显下降（评测里加一道「重复任务」题来量）。

### 2.1 记忆

- **个人版也开记忆**：之前只开在团队版，没有安全或计费上的理由，是产品取舍。改为默认开，管理员可关。
- **自动抽取**：每轮结束后，用便宜模型从对话里抽出值得记住的事实，例如偏好、常用文件、联系人和固定流程，作为 `save_observed_memory` 存下，标「待你确认」，用户可审阅、编辑、删除。
- **按相关程度召回**：用 pgvector 给记忆建向量，按当前消息检索前 K 条注入；没有向量时退回全文检索。仓库的迁移 0000 已经建了 vector 扩展。
- **作用范围**：默认按人。员工自己形成的经验只给该员工用；共享给团队要经过批准，口径和下面的技能一样。

### 2.2 自我改进（技能）

- **做完复盘**：员工完成一件复杂的活（步数超过阈值，或者看板卡验收通过）后，自动做一次复盘。复盘看工具轨迹和结果是否成功，不只看聊天文字，产出一份技能草稿：什么情况下用、步骤、坑点、校验方法。
- **新工具 `save_skill`、`refine_skill`**：员工可以在干活时直接写技能；之后再遇到同类任务、用到这条技能时，按结果修正它。
- **生效方式（用户 2026-11-20 已定 C）**：只对员工自己生效的技能自动启用；要共享给其他员工或团队，才需要本人批准。理由是单个员工学得快，错了影响面也小。
  - 考虑过的另外两种：A 是自动生效、事后可撤销，学得最快，但写错的技能可能会被共享出去；B 是先当草稿、本人批准后才生效（现在的本地学习就是这样），最稳，但学得慢，还要人持续审核。
- **防护**：
  - 技能里不许写密钥、个人隐私或越权步骤，保存前过一遍脱敏检查；
  - 每位员工设技能数量上限；
  - 长期没用的技能自动降权。
- 现有每天一次的「本地学习」保留，作为补充，并改为也看工具轨迹。

## 子项目 3：常驻和主动

**目标**：员工能像 OpenClaw、Hermes、Grok Bot 一样常驻，自己找活干，但不打扰人。

- **心跳**：每位员工可以开一个心跳。它带一份「心跳清单」，例如「每天 9 点汇总邮件」「有新卡就看一眼」，到点醒来按清单检查，没事就静默结束，不产生对话。
  - 复用现有的巡检和例行任务机制，不另造执行器；
  - 上限沿用巡检的每天次数限制。
- **安静时段**：按每人的作息设置，安静时段不发通知、不主动开轮。紧急事件（触发器标了紧急）除外。
- **看板自主认领**：员工能看到派给自己岗位、但还没人领的卡，按优先级自己领、自己做，做完走现有的交付和验收闭环。每位员工有并行上限。
- **收件箱监视**（可选，放在后面）：接入邮箱，新邮件按规则转成任务或触发器事件。

## 子项目 4：常规办公和编码

依据子项目 0 的难题结果再定具体项。目前已知的方向：

- **改完必验**：改代码、改文件之后自动跑校验（测试、构建、重新读回），评测里「改完验证」这一项要做到每题都有。
- **Git 工作流**：开分支、提交、生成 diff 摘要、开 PR 的一组工具，对齐 Codex 的交付方式。
- **重活分流**：大型编码任务按规则建议转交给固定员工 Codex 或 Claude Code，或者用员工设置里的「难任务模型」。
- **验收**：难题通过率不低于 Codex；墙钟时间不超过 Codex 的 1.2 倍。

## 不做

- 社区能力，例如技能市场。
- 视觉模型的截图通道。这一项另外立项。
- 手机操作。

## 反目标（这样做出来就算失败）

- 员工自动写错的技能被大范围共享，导致多个员工一起出错。
- 主动行为打扰人：安静时段发通知、反复开空轮。
- 为了省 token 让通过率下降。
