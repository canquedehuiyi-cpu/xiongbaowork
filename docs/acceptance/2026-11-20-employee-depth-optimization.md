## 评测口径

所有评测都用 `model-e2e.yml` 从 main 手动触发，熊宝与 Codex 用同一个模型（DeepSeek `deepseek-v4-flash`）。

- 难题：`tasks=hard`，`paths=board`，四道题：五个开源项目对比、跨文件重构、终端修构建、网页表单填写。

数字都取自「对标评测 · 对比表」作业日志。每次只跑一遍，没有多次取平均，波动不小：同样的题，Codex 自己的输入 token 在 48 万到 84 万之间。

## 未达成项的原因与下一步

- **token**：每步固定部分已经压到 22.6K 字符，现在大头是步数多（15–29 步）和后段历史长（最长一步 2.8 万–4.3 万 token）。下一步：
  - 用多次评测取平均，确认真实倍数；
  - 看每步工具调用数，核实「一步多调用」在 DeepSeek 上是否真的生效；
  - 根据缓存命中率决定折叠预算还要不要再降。
- **重复任务**：#746 之后复盘已经能触发，但写出的技能没有进入员工的自写技能。推测原因：办公题材料里有邮箱和人名，技能草稿被脱敏规则或网址判断转成待审、没有授予。修复在 `fix/retro-skill-held` 分支进行：复盘把个人数据泛化成占位，日志如实区分「自用生效 / 待审 / 被拒」。
- **墙钟**：和步数直接相关，随 token 那条一起看。
