# 熊宝数字员工全站前端 UI 重构

你负责在当前仓库里实际完成熊宝数字员工网页前端的 UI 重构。用真实路由、组件和业务状态实现新版设计，交付可运行、可验证、可审查的源码和验收记录。按阶段连续实施，在五个核心页面之后继续完成其余前端入口，直至逐路由核对。请用中文沟通。

## 工作基线

- 从带有本设计材料的 `codex/ui-design-studio-reference` 分支启动。检查仓库默认分支的最新提交，在独立施工分支上使用合适的最新基线。若在现有施工分支继续，先保留已有修改，并从设计材料分支把 `docs/design/ios-studio/` 取到本地供参考。网页应用在 `openbot/app`。先检查当前分支、提交、工作区和依赖版本，阅读适用的 `CLAUDE.md`、`AGENTS.md` 以及相关项目文档。记录起点提交。保留已有改动，在当前独立工作分支上分批修改。
- 优先复用项目已有 React、Vite、TanStack Router、TanStack Query、Tailwind 和组件体系。路由清单从 `openbot/app/src/routes` 生成。每个路由标记壳层、主要组件、各数据状态、交互与验证证据。重定向路由单独标明。
- 用户验收当前工作分支。提交、推送、合并、生产发布及运行时切换交由用户决定。旧的浅色暖金参考和先前的蓝紫、红色通栏预览属于历史方案。视觉以本任务指定的黑白红新版为准。

## 设计基线

在仓库的 `docs/design/ios-studio/` 目录里打开以下五张 PNG，逐张确认页面结构与视觉重点。该目录的 `index.html`、`theme.css` 和 `preview.js` 可用来确认间距、字阶、颜色及插图构造。预览里的数据和静态控件仅用于说明外观。把其中的设计规则转化为应用自身的主题变量、样式和组件变体，保留实际数据和交互链路。

| 效果图 | 核心路由 | 页面重点 |
| --- | --- | --- |
| `01-任务看板.png` | `/tasks` | 开放式页头。四项指标合进同一遥测面板。保留设备和周期筛选、需要操作与查收结果、任务列表与泳道。状态分布从同一查询结果计算，处理总数为零的情况。 |
| `02-Waker.png` | `/reachability` | 左侧标题和四个接入入口，右侧悬浮聊天示意。保留已接入聊天的筛选、列表和卡片、行操作、送达记录及接入流程。 |
| `03-自主工作.png` | `/autonomous` | 用克制的芯片与信号路径表现触发和执行。把四项指标放进一块面板，保留创建、查看、编辑、筛选、启停和三种真实触发类型。 |
| `04-员工管理.png` | `/wakers` | 角色档案横向排版，个人分身可用局部红色强调。保留员工与群组页签、角色模板、新建入口、员工卡片、运行状态、环境、筛选和最近运行。 |
| `05-能力与资源.png` | `/resources` | 六个常用资源入口使用连续面板，当前入口用细红线标记。插件市场、我的插件、分类与详情保留原有行为。 |

- 主色取熊宝脸谱的黑、白、红。深色画布可从 `#0D0D0E` 起步，卡面使用石墨灰，主文字用 `#F6F6F6`，强调红可从 `#FB5257` 起步。字、底、状态及焦点的最终搭配以实际对比度为准。
- 延续新版的开放式标题、清晰的字阶、边距网格、低对比细描边、轻微内高光、哑光材质、圆角分段控件。白色用于主操作和主信息，红色集中在选中、需要关注的状态、品牌及少数信号线。卡片的区分主要依靠结构、间距和亮度。
- 共享导航、筛选器、卡片、表格和弹窗各用同一套规则。每个页面只保留有意义的视觉重点。插画用于 @Waker 和自主工作的页头，具备无图时仍完整的正文与操作。企业后台、设置、审批和对话以可读性与信息密度为优先。
- 使用现有 `BrandLogo`、`BearMascot` 和品牌资产。`熊宝-logo.png` 与 `熊宝-头像.png` 用于核对视觉，不重新生成角色或改变红黑脸谱。验证深浅主题下的标识、文字和状态色；暗色最贴近效果图，现有主题偏好和切换行为继续有效。

## 全站范围

先统一主题、工作台壳和公共控件，再完成五张图对应的核心页面及其详情、创建、编辑和空态。随后根据路由清单完成以下界面，复用公共样式能覆盖的页面也逐页检查。

1. 登录、登录请求、引导与首页。
2. 对话、员工对话、聊天频道和群组，包含会话列表、消息、附件、输入区、执行状态和审批交互。
3. 员工详情、员工组装、角色模板、群组管理、团队机器人和我的分身。
4. 技能、知识库、记忆、职责、例行任务、审批、流程编排及 WakerFlow 列表、详情、新建与导入。
5. 资源各子页、插件授权与详情、连接账号、模型或计划等当前仓库真实存在的入口。
6. 设置与管理后台，包括当前存在的账号、密码、组件、人员、身份提供方、凭据、设备、审计、企业与权限相关页面。
7. 统一移动和窄窗口下的导航、表格溢出策略、表单、弹层、Toast、错误页，以及键盘焦点与状态呈现。

## 实施边界

- 工作集中在 `openbot/app`。优先从 `src/styles.css`、现有 `AppShell`、`AppSidebar`、`SidebarShell`、`PageShell` 和 `components/ui` 入手。用共享变量和组件变体减少逐页覆盖。保留现有组件的可访问属性、行为和调用契约。
- 复用所有真实查询、权限门槛、状态字段、操作与错误处理。保持 URL、查询参数、深链接、后退与刷新、登录状态、审批、授权、租户与设备边界。对照现有实现检查完整交互，避免把截图中的数字、员工、插件或聊天记录写进应用。加载、空、无匹配、错误、部分数据、未授权、禁用和提交中都要有明确反馈。
- 这次的修改属于前端呈现与交互组织。后端协议、数据模型、数据库迁移、设备端、模型调用、计费、环境凭据和生产配置按原契约使用。遇到某个界面所需能力确实缺失时，记录现有行为与缺口，继续完成其他界面。上线前的核验在独立本地环境和测试数据下完成。
- 尊重用户缩放和减少动态效果偏好。检查状态在没有颜色时仍有文字或图标可辨识，支持键盘导航、焦点回归、无障碍名称，以及手机和桌面尺寸。图片或装饰适度加载，布局保持稳定。

## 验证与交付

1. 记录改造前的可用性与已知失败，准备本地测试数据，优先复用 `openbot/app/tests/parity` 的截图与示例数据。按 `openbot` 的锁文件、Bun 版本及仓库说明准备依赖与应用配置。使用隔离端口。Windows 浏览器路径按实际环境指定。
2. 在 `openbot` 下运行 `bun run --cwd app typecheck`、`bun run --cwd app build`，以及仓库要求的前端测试。运行与侧栏、路由、任务、员工、IM、自主工作、资源和审批相关的现有回归。记录每条实际命令与结果。失败时定位并修复属于本次改造的问题，列出基线已存在的失败及对应证据。
3. 用浏览器核对五个核心页面。提供 1440×900 的同尺寸改造后截图，覆盖有数据与空态，并在 1280×800、1024×768、约 390px 手机宽度检查布局。补齐其他路由的验收清单，至少为登录、对话、员工详情、流程、设置和后台各提供代表性截图。检查长文本、筛选组合、错误重试、主题切换、键盘操作和弹层开关。
4. 在本地测试环境实际走通导航、筛选与清空、列表和泳道切换、任务详情和查收、员工或群组的相关入口、IM 接入入口、自动任务创建表单和启停、插件详情与权限状态。凡涉及写入的验证，使用可丢弃的测试数据并核对结果。示例数据截图、模拟交互和真实后端联调分别标明。未取得证据的项明确记录原因和复现条件。
5. 交付改动说明、完整路由覆盖清单、构建与测试结果、截图位置及待用户验收项。汇报当前分支、起点提交和实际变更范围。交付物区分已实现、已验证、待验证和受阻。全站工作继续推进，直至授权范围内可完成的前端改造和验收全部完成。
