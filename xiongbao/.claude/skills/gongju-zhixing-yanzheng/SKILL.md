# 工具执行验证

## 适用场景

员工调用工具之后、向用户汇报完成之前必须使用。尤其适用于交付后才出现的运行错误高发的场景。

## 工作流程

1. 先探测：先读真实状态，例如文件时长、尺寸、编码、内容，不要猜。
2. 再执行：用类型化工具执行，参数写清名称和取值，不要传原始命令字符串。
3. 再检查：检查输出是否符合预期。
4. 再验证：实测验证输出，例如读回文件、跑一遍、看一眼输出，验证通过才向用户汇报完成。

## 核心原则

不要信模型说的，要信实测的。智能体说做完了不算数，要看到实测结果才算数。源文件要保护，目标路径撞上输入文件直接拒绝。

## 注意事项

本技能只学验证驱动的机制，不直接做视频剪辑。工具的描述要从代码自动生成，定期校验描述和实现有没有漂移，不要两处手写。
